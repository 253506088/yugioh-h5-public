# AI 卡片名录与 2014 年以后年度维护交接

日期：2026-09-22。适用于继续实现 2014、2015 及以后年份卡片的开发同事。年度效果开发仍按 [卡池按年推进方案](../游戏王卡片按年切片推进方案.md) 和 [2013 批次交接](2013批次交接.md) 执行；本文补充 AI 导入依赖的数据库、身份与名录维护。

## 先分清三个数据层

| 数据层 | 当前基线 | 用途与边界 |
| --- | --- | --- |
| 本作卡池 `DuelData.CARDS` | 6,275 张可编入卡组的卡；1999—2013 年度身份加部分自建卡 | 真实内部 ID、类型、数值、年份、效果实现状态。只有这一层决定卡能否进入本作决斗。 |
| 本作三语资料 `DuelCardLocales` | 当前 6,275 张卡的中、英、日名称和说明 | 图鉴显示和 AI 精确认卡使用的权威名称，不能仅补英文显示名。 |
| 全库名录 `DuelCardCatalog` | **14,981 行**，包含别画/同名异号 | 从上游三语 CDB 导出的名称、密码和 alias，覆盖本作尚未收录的卡，用来区分「未收录」和「无法识别」。行数不等于已实现卡数，也不代表去重后的卡数。 |

全库已经包含许多 2014 年及以后卡片。**推进一年不等于把该年的卡再加一次到全库；现有快照有记录时，完成年度卡池和三语接入即可。** 全库只有名称资料，没有效果处理器，不能因为能查到一张卡就把它标为 playable。

## 来源和生成关系

当前上游是 [mycard/ygopro-database](https://github.com/mycard/ygopro-database)，固定提交 `ac5d8fb80465e74b33f3b4a294e3b22c02d743f2`。本地保留：

- `data/locales/sources/<commit>/zh-CN.cdb`
- `data/locales/sources/<commit>/en-US.cdb`
- `data/locales/sources/<commit>/ja-JP.cdb`

来源链必须完整：

```text
年度来源 data/yearly/<year>/cards.json + 对应 manifest/catalog 快照
    → scripts/import-early-cards.mjs → src/early-cards.js
    → 本作效果模块与注册 → implementationStatus

data/locales/source-manifest.json → 固定提交的三语 .cdb + SHA-256
    → scripts/sync-locales.mjs
       → data/locales/cards.json（含 source.files、哈希与当前卡池三语）
       → src/card-locales.js
    → scripts/build-card-catalog.mjs（读取 cards.json 的 source.files）
       → src/card-catalog.js

卡池 + 三语资料 + 全库名录 + data/card-aliases.json
    → src/card-resolver.js → 导入状态与工坊草稿
    → scripts/build.mjs → 根目录 index.html
```

`source-manifest.json` 和 `cards.json` 内嵌的 `source` 必须来自同一套快照。只换前者而不重新同步，名录生成器仍会读后者指定的旧 CDB。生成器会校验三个文件的 SHA-256；校验失败时应恢复正确来源，不能为了通过校验随意改哈希。

## 每个新年份的必做顺序

以 2014 为例，以下是后续年度开发流程，本次交接没有提前采集或实现 2014：

1. 准备和采集年度元数据，并核对来源身份、首次 OCG 日期、再版、与已有卡池复用的身份：

   ```powershell
   npm.cmd run cards:year -- 2014
   npm.cmd run collect:years -- --scope data/yearly/scope-2014-2014.json --no-images
   npm.cmd run cards:import
   ```

2. 接入新年的类型、召唤机制、效果和测试。新类型（尤其 2014 起的灵摆）必须保留正确素材/刻度/区域规则。尚未实现的效果保持 `pending`；浏览器构建和 Node 入口都要加载对应效果分册，不能只改 `scripts/build.mjs`。

3. 使用已有快照同步本作三语资料，再重建全库名录：

   ```powershell
   npm.cmd run locales:sync
   npm.cmd run cards:catalog
   ```

   `locales:sync` 是离线操作。检查 `output/localization/card-coverage.json`，必须处理缺身份、缺名称/说明、缺灵摆文本和缺百科来源，不忽略命令退出码。新增供应方/图片身份和百科依据应保存到正式 `data/`，不要依赖只存在于忽略目录的临时下载。

4. 核对 AI 本地匹配从 `not-in-pool` → `pending` → `playable` 的变化。状态依据是运行时 `DuelData.CARDS[id].implementationStatus`；仅 `require('./src/early-cards.js')` 会看到部分尚未由效果模块更新的状态，测试应像现有测试一样先加载 `advanced-engine.js` 和 `advanced-effects.js`。

5. 更新显示范围与本年交接，然后构建、验证：

   ```powershell
   npm.cmd run build
   npm.cmd run test:ai-import:unit
   npm.cmd run test:ai-import:browser
   npm.cmd run test:i18n
   npm.cmd test
   ```

   同时执行本年度的规则、逐卡 sweep、模拟和浏览器检查。AI 导入通过不能替代效果正确性验收。

## 什么时候需要更新上游 CDB

遇到新年度卡在现有快照中没有记录、官方名称/翻译需要修订、别画 alias 缺失等情况，再执行：

```powershell
npm.cmd run locales:update
npm.cmd run cards:catalog
npm.cmd run build
```

`locales:update` 会联网获取上游的新固定提交及三语 CDB，更新来源清单、哈希和本作三语生成文件；可能补取缺少的百科链接。审查新提交、CDB 内容差异及名称变更后，将新来源目录一并提交。保留已有固定快照便于追溯，不直接编辑旧 CDB，也不下载执行上游 Lua 脚本。

必须确认更新后 `cards.json` 和 `source-manifest.json` 的提交号/文件路径/哈希相符，`card-catalog.js` 顶部生成注释指向同一提交。14,981 是本次快照基线，后续更新可以改变；不要为保持这个数字而删行。

## 身份和别名规则

- 内部 ID 必须稳定，不按年份重排。年度供应方身份复用已有卡时，保留原 ID，避免旧卡组/存档失效。
- `providerId` 是卡片密码；数值存储可以省略前导零，YDK/YDKe 会明确标为密码输入。不要把卡名 `7` 当成密码 7。
- 全库每行是 `[密码, 中文名, 英文名, 日文名, alias]`。`alias` 用于把别画等折叠到主号，例如青眼白龙 `89631140 → 89631139`。不要为别画创建重复效果卡。
- 没有 `providerId` 的旧手工卡仍靠三语名匹配；全库密码可经官方名称回到这些卡。不要为了补密码而凭记忆填写近似编号。
- 维护简称/繁体写法使用 `data/card-aliases.json`，右侧写经名录核实的官方名称。模型不能生成本作内部 ID 或为未确认名称自动选近似卡。
- 精确查询顺序是「数据库轻规范化 → 自有名轻规范化 → 数据库重规范化 → 自有名重规范化」。当前五组自有名撞权威名的覆盖是已知规则，见 [原始设计第 2.2 节](../docs/ai-deck-import-design.md)。若新年份带来新冲突，应逐条核验身份并增加明确用例，不能直接放宽断言数量或修改为先到先得。

## 交付前验收清单

- 新增卡的中、英、日官方名分别精确命中同一内部 ID；主号与实际别画密码命中同一张卡。
- 新年度未实现卡仍是 `pending`，不能绕过 `DuelDecks.analyze` 保存为可对战卡组。
- 已完成的本年卡不再标为 `not-in-pool`；更晚年度的已知真卡仍能正确标为未收录，而错字/歧义仍需确认。
- 「青眼白尤」仍需确认；「雷鸣」与「雷-鸣」不混淆；五组历史名称覆盖和「7」的回归不被破坏。
- 多卡组、主/额外类型、同名数量上限、副卡组备注、取消与三语手机布局仍通过；不合法草稿刷新后保留原分区供修正。
- 同一固定快照连续执行 `cards:catalog` 得到相同字节；全量构建包含最新语言库和全库名录。

## 提交与排除

提交正式年度来源/清单、三语 `.cdb` 固定快照、来源清单和哈希、生成的三语资料与全库名录、别名表、规则/界面源码、测试、交接文档及根目录 `index.html`。全库名录虽然是生成文件，仍需提交，以支持离线构建和双击 HTML。

不要提交 `output/` 内抓取临时页面、截图、测试报告、模拟录像、原始调试请求，以及本地 `.env` / `.env.local` 或 API 令牌。`.cdb` 是正式来源必须保留，自动产生的 `.cdb-wal` / `.cdb-shm` 是运行副产物，已经忽略。若引入新的临时目录，应在 `.gitignore` 写明用途，不要用一条宽泛的 `*.cdb` 把正式数据库排除掉。

当前 AI 导入说明：[docs/ai-deck-import.md](../docs/ai-deck-import.md)。运行时名录查询完全离线；联网模型/网页抓取只是内容来源，不会自动改动这些数据库。
