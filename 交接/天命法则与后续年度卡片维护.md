# 天命法则与后续年度卡片维护

日期：2026-09-24。适用于继续采集、导入和实现 2015 年及以后卡片。

## 结论

**不会改变卡片采集文件格式、年度快照、密码／ID、三语资料或 AI 名录生成流程，但会影响卡片效果的实现方式和验收范围。** 新模式是独立规则层，不向卡库写特殊效果，也不修改导入器生成的 `CARDS`。后续仍按 [2014 批次交接](2014批次交接.md) 与 [AI 卡片名录交接](AI卡片名录与2014以后年度维护交接.md) 推进。

现在必须把卡片效果放进统一的移动、来源、召唤、抽卡和生命值接口。直接改区域数组、LP、基础攻守的卡片可能绕过随机法则，造成「经典模式能用、天命模式失效」。规则层能覆盖现有通用接口，不承诺拦截任意手写的状态修改。

## 文件和加载顺序

- `src/rule-modes.js`：25 条规则定义、三语说明、引擎扩展、规则行动、阶段和事件处理。`DuelRuleModes` 是公开 API。
- `src/rule-modes-ui.js` / `.css`：图鉴、分类／搜索、模式选择、开场揭晓、战场提示；不抽随机数、不计算行动合法性。
- `advanced-engine.js`：构造函数安装一次、规则行动分派、响应窗口、中心召唤区域、普通抽卡覆盖点、持续效果免疫检查。
- `advanced-effects.js`：盖放当回合发动的规则许可。
- Node：`advanced-engine.js` 末尾在全部年度效果之后加载 `rule-modes.js`。浏览器：`scripts/build.mjs` 在全部年度效果和 `log-engine.js` 后、界面前加载。**新年度分册放在规则层之前，两条加载链必须一致。**
- 联机：`server/service.mjs` 房间只接受 `off` / `random`；服务器抽取并结算。`projection.mjs` 逐项投影公开状态，禁止直接发送引擎快照。`pvp-client.js` 仅展示服务端合法行动。
- 赛事：`settings.ruleMode` 保存模式；每场独立创建引擎，录像初始快照含实际法则。

## 状态契约

`state.ruleMode={id,version:1,source,players:[{},{}],…}` 是唯一权威。缺失即经典模式。`id` 整局不改变，恢复快照不再执行抽签。普通构造支持 `ruleMode:'random'`；固定 ID 仅供代码测试，产品不提供任意改写当前对局规则的按钮。不得在 UI、`restore`、AI 复制或 PVP 投影时重新抽取。

玩家计数器都放在 `ruleMode.players`，包括发动次数的回合号和次数、苦肉、真空、额外通常召唤；连锁奖励和已回响实体 UID 也保存在这个 JSON 对象内。不要把闭包、函数、`Infinity`、`Map` 或仅保存在引擎临时字段的计数作为必须恢复的状态。临时重入保护可以用 `_ruleDrawing`，不能影响可保存的选择。

怪兽标记：`ruleWanted`（通缉）、`ruleStars`（召唤时素材星数合计）、`ruleCannonTurn`（中心倍攻回合）、`ruleAtkLoss`（卷刃累计损失）。`move` 正常离场时清理；`describe` 将需要离场后判断的标记写入事件快照。`ruleNoEffect` 可表达真正的效果移除；二重怪兽同时沿用现有 `isNormalMonster`。普通卡片效果无效 `negated()` 也按本模式约定进入无效果分支。

## 新卡的实现要求

| 操作 | 使用的接口与原因 |
| --- | --- |
| 送墓／除外／返回／检索 | `e.move(uid,to,{kind,source,byOwner})` 或年度工具 `moved`。必须区分 `cost-*`、`effect-*`、`rule-*`，保留 `source`。这样灵魂解放、观星、遗产、睡眠计时和免疫都能判定。 |
| 抽卡 | `e.draw(owner,n)`，不要从 `deck` 手动 `shift` 再 `hand.push`。效果抽卡不得设置 `state.inDrawPhase`，否则会被当成通常抽卡替换。 |
| 检索 | `e.search`，或从卡组到手牌的 `move(...,{kind:'effect-search',source})`。不要在同次移动后再自行发一遍 `added/search`，会重复触发观星。 |
| 破坏 | `e.destroy(uid,source,battle)`。不要拿 `move` 冒充效果破坏。法则本身的强制规则破坏是独立路径，可以越过卡片保护。 |
| 召唤 | `normalSummon`、`special`、`performXyz`、`performLink` 等。保留召唤事件的 `materials` 快照。先描述素材再移走，记录其当时等级和来源；尊卑有别不能用当前叠放素材数反推。 |
| 攻守 | `e.modify` 或持续 `passive.stat`。必须携带来源并调用 `unaffected`。基础数据不得修改。规则数值在卡片数值之外叠加，不能被卡片无效清掉。 |
| 代价 LP | `e.payLP`：必须保留至少 1 LP。不得当作效果伤害。 |
| 伤害／回复 | 卡片用 `e.damage` / `e.heal`；游戏法则的不可干预变化用 `ruleDamage` / `ruleHeal`。 |
| 失去 LP | 新增 `e.loseLP(owner,amount,source)`：不是代价或伤害，可以致死，最低 0，在连锁结算完成时正常判负。已将「灵魂补充」改用这个接口。 |
| 效果发动 | 走 `prepare` / `commitPrepared`，不要直接调用卡片 `resolve` 绕过次数计数。召唤手续必须标 `inherent`，避免被计划经济误计。 |

持续效果如果自行扫描区域并直接改变对方怪兽，必须检查 `e.unaffected(target, source)`，不能认为非取对象效果不受免疫限制。基础 `passive.stat` 路径已增加法则免疫检查；新增私有持续实现仍需自己传来源。

多操作卡片要考虑真空：手牌由正数变 0 会登记一次奖励，即便紧接着效果又抽到卡，奖励也不会取消。抽卡任务可以在当前原子步骤之后执行，但不能用处理时「现在是否仍空手」替代发生时条件。

## 明确的规则口径

完整 25 条见 [使用说明](../docs/rule-modes.md)。后续实现尤其注意：

1. 先攻第一回合仍无通常抽卡；命运轮盘从之后的抽卡阶段开始。
2. 半攻守向上取整到整数；支付半 LP 向下取整。两种规则的取整不同。
3. 尊卑有别的超量／连接星数为素材星数**合计**，连接作素材取连接值，无法追溯时取阶级／连接值。
4. 灵魂解放优先替换送墓，场上的灵摆也除外，不先转为表侧额外。代价如果明确要求「必须送到墓地」仍须由卡片代价验证器负责确认可支付。
5. 魔导回响跟踪物理实体 UID，回手后再发动仍为第二次；发动无效不重新盖放，效果无效但发动成立仍按发动处理。
6. 狂欢连锁奖励按成功处理的每个效果累计，整条结算完再抽。不能在每个环结束时立即抽牌改变其他环的状态。
7. 墓地待回收时间用 `sentTurn`，T 回合送墓到 T+3 回合结束才到期。再入墓重置。
8. 苦肉每位玩家每个全局回合一次，可在对方回合响应窗口操作，属于不入连锁的规则行动。

## 后续年度验证

正常年度回归和逐卡扫描不变，另运行：

```sh
npm run test:rule-modes
npm run test:pvp
npm run test:rule-modes:browser
npm run test:rule-modes:simulation
npm test
npm run build
```

为新年度的移动／无效／召唤特色卡，至少增加几个真实组合：灵魂解放下送墓代价和素材、原初洪流／尊卑有别免疫、魔导回响第二次发动、零手牌后同环抽卡、素材离场后的来源星数。测试应断言最终去向、LP、次数及连锁，而不只是「没有异常」。

`tests/rule-modes-simulation.cjs` 逐法则跑两种配对（旧牌和 2014 牌），验证完成及卡片守恒；失败时 `output/rule-modes/invalid-*.json` 保存回滚前现场。`DUEL_RULE=<id>` 和 `DUEL_MIRROR=0/1` 可定位一场。以后用新年份代表卡组增加配对。

提交正式源码、测试、文档和根目录 `index.html`；`output/rule-modes/` 中所有现场、截图、试验脚本、测试构建不提交，`.gitignore` 已说明。没有新增采集依赖，也没有改变任何现有卡片 ID。
