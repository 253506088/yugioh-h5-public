# 新增卡片系列归属规范（防止「本家不认本家」）

日期：2026-09-26。适用于 2015 年及以后的每个年度批次，也适用于任何新增或复用卡片身份、任何写「系列」判断的效果代码。

事故经过、影响范围和修复步骤见根目录的[《系列本家识别问题修复方案》](../系列本家识别问题修复方案.md)。本文只规定以后怎么做。

---

## 1. 为什么要有这份规范

2026-09-25，用户发现「黑羽-晓之希洛克」在场时，「黑羽-黑枪之布拉斯特」不能从手牌特殊召唤，「黑羽-月影之卡鲁特」也不能给希洛克加攻。原因是布拉斯特、卡鲁特沿用旧扩展卡的效果代码，只认 `family === 'blackwing'`；而按年份导入的卡 `family` 一律是 `'early'`，没有人给这些新成员补上旧系列标签。核对全卡池后，同样的问题出现在黑羽、同调士、废品、HERO、希望皇、拟声四系列、银河、竹光、电子龙这 9 组系列里，共影响 141 张卡。

系列判断出错有两种，本规范都要防：

- **漏认（本家不认本家）**：确实属于 X 系列的卡，没被 X 的支援认出来。
- **误认（外人冒充本家）**：不属于 X 系列的卡，被当作 X。例如 `series(m,'HERO')` 会把「英豪挑战者」当作 HERO。

两者的共同根源：系列归属没有统一的口径和入口，每个年份各写各的；也没有自动测试把系列判断和权威数据对照。

## 2. 唯一口径：以 OCG 系列码为准

### 2.1 真值来源

- **数据**：`data/locales/source-manifest.json` 记录的 CDB 文件（已提交，离线可用）。取表 `datas` 的 `setcode` 字段。每张卡最多有 4 个 16 位系列码，要用 BigInt 读取。
- **判定**（与 YGOPro 的 IsSetCard 相同）：卡片的某个系列码 `s` 满足 `(s & 0xfff) === (code & 0xfff) && (s & code) === code`，这张卡就属于系列 `code`。这个规则已经包含：
  - 子系列：强袭黑羽、黑羽驯鸟师都属于「黑羽」（0x33）。
  - 卡面的「在规则上也当作『X』卡使用」。
  - 衍生物：「黑羽-黑冠衍生物」属于 0x33，「同调士衍生物」属于 0x1017。
- **英文名子串只能作兜底**，用于没有系列码的卡（本作自造的衍生物、自制卡）。

### 2.2 卡名和系列是两回事

卡面上的「X」，要先分清指的是**卡名**还是**系列**：

- **卡名**：例如「电子龙」这张卡，或者「这张卡的卡名当作『电子龙』使用」。用 `is()` 或 `e.cardNameId()` 判断。
- **系列**：例如「『电子龙』怪兽」。用第 3 节的统一入口判断。

### 2.3 容易出错的英文名

| 情况 | 例子 | 正确归属 |
| --- | --- | --- |
| 子串误中 | Heroic Challenger、Hero Kid、Oscillo Hero 包含 "hero" | 不是 HERO（OCG 写作「ＨＥＲＯ」） |
| 子串误中 | Skyscraper 包含 "scrap" | 不是废铁 |
| 子串误中 | XYZ-Dragon Cannon 包含 "xyz" | 不是「超量」魔法／陷阱 |
| 子串误中 | Synchronized Realm 包含 "Synchron" | 不是同调士 |
| 子串误中 | Cocoon of Evolution、Huge Revolution 包含 "evol" | 不是进化 |
| 子串误中 | Cybernetic Zone 以 "Cyber" 开头 | 不是「电子」卡（日文「サイバネティック」不含「サイバー」） |
| 名称相近 | Black-Winged Dragon | 不是黑羽 |
| 名称相近 | Dark Magician of Chaos、Skilled Dark Magician | 不是「黑魔术师」系列 |
| 范围过宽 | 单用 "Magician" 会命中 65 只怪兽 | OCG「魔術師」只有 22 只，只在灵摆怪兽范围内一致 |
| 卡面写「也当作」 | Lesser Fiend、Celestial Sword - Eatos、Contrast HERO Chaos、Ojamuscle | 分别属于恶魔、圣剑、元素英雄、扰乱 |
| 只在 OCG 日文名里成立 | Steelswarm（インヴェルズ）、Invasion of Flames（侵略の炎）、Number 23: Lancelot（ランスロット）、Neo Space（ネオスペース） | 分别属于入魔、侵略的、兰斯洛特、新宇 |
| 子系列 | Assault Blackwing、Blackwing Tamer | 属于黑羽 |

### 2.4 有意偏离

如果本作有意不按 OCG 口径处理某张卡，必须同时做两件事：登记到守卫测试的例外表（第 6 节），并写进该卡的 `implementationNote`。不登记的偏离一律视为缺陷。

## 3. 写代码的规则

### 3.1 必须遵守

1. **系列判断只能走统一入口。**
   - 年份卡：`series(m,'英文系列名')` 或 `arch('…')`。修复方案阶段二完成后，改为 `D.inArchetype(card,key)`，按系列码判断。
   - 旧扩展卡用到的系列：一律用 `isFamily(CARDS[id],key)` 或对应的标志位。新代码不得再写 `CARDS[id].family==='key'`，因为 `family` 只能有一个值，多系列的卡会漏认。

   | 系列键 | 系列 | 系列码 | 旧代码怎么判断 | 标签由谁写入 |
   | --- | --- | --- | --- | --- |
   | `blackwing` | 黑羽 | 0x33 | `family`；同调素材用 `tunerFamily` | 回填：`family`＋`families` |
   | `synchron` | 同调士 | 0x1017 | `family`；同调素材用 `tunerFamily` | 回填：`family`＋`families` |
   | `junk` | 废品 | 0x43 | `junk` 标志；`isFamily(c,'junk')` 同时包含同调士 | 回填：`junk`＋`families` |
   | `hero` | HERO | 0x8 | `isFamily(c,'hero')`；融合素材 `{family:'hero'}` | 回填：`families` |
   | `elemental` | 元素英雄 | 0x3008 | `elemental` 标志；融合素材 `{elemental:true}` | 回填：`elemental` |
   | `masked` | 假面英雄 | 0xa008 | `masked` 标志 | 导入器按卡面设置 |
   | `utopia` | 希望皇（超量） | 0x107f | `family`；电光皇的升阶用 `rankUpFamily` | 回填：`family`＋`families` |
   | `gagaga`／`gogogo`／`dododo`／`zubaba` | 我我我／隆隆隆／怒怒怒／刷拉拉 | 0x54／0x59／0x82／0x8f | `isFamily` | 回填：`families` |
   | `galaxy` | 银河 | 0x7b | `family` | 回填：`family`＋`families` |
   | `bamboo` | 竹光 | 0x60 | `family` | 回填：`family`＋`families` |
   | `qliphort` | 机壳 | 0xaa | `family`，以及 `tributeFamily` 等 | `effects-2014-support.js:7` |
   | `crystron` | 水晶机巧 | 0xea | `crystron` 标志 | 回填：`crystron` |
   | `cyberDragon` | 电子龙 | 0x1093 | `cyberDragon` 标志；融合素材 `{cyberDragon:true}` | 回填：`cyberDragon` |

   「回填」指修复方案第 4.1 节 A 放在 `src/chronicle-costs.js` 的那段代码。它按英文名（区分大小写）和「This card is always treated as」说明给所有卡打标签，所以本年新成员只要名字里有系列词，就会自动获得标签。

2. **一个系列只能有一套判断。** 新分册需要时，从公共 API 取（`DuelChronicle` 的 `series`／`arch`，或本年度工具对象），不要在分册里另写一份口径不同的判断。反例：「恶魔」在 2003 年和 2013 年各有一套判断，前者认「也当作」说明，后者不认。

3. **判断要带上卡面的全部限定条件**：卡种（怪兽／魔法／陷阱）、灵摆、调整、等级。子串匹配配上卡种过滤，就能消除大部分误认。例如 `pend(m)&&series(m,'Magician')` 在灵摆怪兽里是准确的；反例是世代之力检索「超量」魔法／陷阱时没有过滤卡种，结果连 XYZ-神龙炮也能检索。

4. **素材条件写系列时**，用 `{family:key}`（经过 `isFamily`）或年份层的 `{series:'X'}`；「X 调整」用 `tunerFamily`，不要用 `tunerId` 列表代替。

5. **新出现的系列名必须登记。** 代码里第一次用到某个系列名（`series(m,'X')`、`arch('X')`、`{series:'X'}`、groups 分组表），要把它加进守卫测试的映射表（名称 → 系列码）。如果它只是卡名片段、不是系列，也要标注出来。修复方案阶段二完成后，没登记的名称会让测试失败；在那之前，按第 4 节用附录脚本人工核对。

### 3.2 禁止

- 用 `officialName.startsWith(...)`、临时正则或手写 id 列表代替系列判断。卡面指定的是具体卡名时除外。
- 为了「让某张卡能用」，在效果分册里单独改它的 `family`、`families` 或 `series`。系列标签只能由统一的回填代码（阶段二后改为系列码数据）生成；确实需要例外的，登记到第 6 节的例外表。
- 复用旧卡身份时，让同一张卡同时保留两套等价的处理（会重复触发）。
- 把旧卡的 `family` 改成别的值。旧处理是按它判断的。

### 3.3 复用旧卡身份时

导入器遇到英文名和旧卡相同的新年份卡，会复用旧 id 并标 `existing:true`。这时要做四件事：

1. 确认这张卡保留哪一套处理。看 `src/chronicle-costs.js` 的 `reused` 表：在表里的，停用年份处理，保留旧处理。
2. 如果保留旧处理，用守卫测试确认旧处理的系列判断能认出**本年所有**同系列成员。
3. 如果为它写了年份处理又决定保留旧处理，把年份处理登记进 `reused` 表停用。
4. 为这张卡写至少一条「旧支援 × 本年新成员」的测试。

## 5. 守卫测试

- **文件**：`tests/archetype-membership.test.cjs`，由修复方案阶段一建立，已列入 `scripts/run-checks.mjs` 和 `test:chronicle`。
- **数据**：用 `node:sqlite` 只读打开 CDB，不需要网络；项目要求 Node ≥ 22.13。浏览器和 PVP 服务不读 CDB，运行时靠回填的标签；阶段二以后，靠写进卡片数据的系列码。
- **第 1 部分：旧扩展系列**。第 3.1 节表里的每一行做双向对照：
  - 有系列码的卡，必须被本作的判断认出（查漏认）；
  - 被本作的判断认出的卡，必须有系列码（查误认）。
  - 适用范围与旧代码一致：黑羽、同调士、废品、HERO、元素英雄、假面英雄、拟声四系列、银河、机壳只看怪兽；希望皇只看超量怪兽；竹光、水晶机巧、电子龙看所有卡。
- **第 2 部分：全部系列名**（阶段二以后生效）。扫描 `src/` 里所有 `series(…,'X')`、`arch('X')`、`{series:'X'}` 和 `const groups={…}` 分组表中的名称。每个名称都必须在映射表里登记系列码，或标注「卡名片段」；然后按映射表做双向对照，差异必须为 0，或者已登记为例外。
- **失败时怎么处理**：先看输出的卡名，判断属于哪种情况：
  1. 回填规则没覆盖到，通常是新成员名字里没有系列词。阶段一时扩展回填规则；阶段二后确认卡片数据里有系列码。
  2. 判断写错了，例如子串误中、缺卡种过滤。修改判断。
  3. 本作有意偏离 OCG。登记例外（第 6 节）。

  **不得通过放宽断言或删除对照行来让测试通过。**

## 7. 写代码前先问自己五个问题

1. 卡面上的「X」指的是卡名，还是系列？
2. 这个系列在旧扩展卡里有没有系列键（第 3.1 节的表）？有的话，旧处理能认出本年的新成员吗？
3. 我的判断会不会误中名字相近的卡？跑附录脚本的 `--all` 看一看。
4. 本年有没有「也当作 X」的卡、X 的子系列，或者会产生 X 衍生物的卡？
5. 我写了「旧支援 × 新成员」和「新支援 × 旧成员」的测试吗？

for(const [name,code,scope,pred] of LEGACY){
  const skip=EXCEPTIONS[name]||{};
  const fn=pool.filter(c=>codesOf.has(c.id)&&scope(c)&&has(c,code)&&!pred(c)&&!skip[c.officialName]);
  const fp=pool.filter(c=>codesOf.has(c.id)&&scope(c)&&pred(c)&&!has(c,code)&&!skip[c.officialName]);
  failures+=fn.length+fp.length;
  console.log(`${fn.length||fp.length?'✗':'✓'} ${name} 0x${code.toString(16)}：漏认 ${fn.length}，误认 ${fp.length}`);
  for(const c of fn)console.log('    漏认 '+label(c));
  for(const c of fp)console.log('    误认 '+label(c));
}
if(process.argv.includes('--all')){
  console.log('\n== 第 2 部分：代码中出现的系列名（series()/arch()/{series:}，自动推断系列码，需人工复核）');
  const names=new Map();
  for(const f of fs.readdirSync(path.join(root,'src')).filter(f=>f.endsWith('.js'))){
    const s=fs.readFileSync(path.join(root,'src',f),'utf8');
    for(const re of [/series\((?:[^,()]|\([^()]*\))*,\s*'([^']+)'\s*\)/g,/\barch\(\s*'([^']+)'\s*\)/g,/series:\s*'([^']+)'/g])
      for(const m of s.matchAll(re))(names.get(m[1])||names.set(m[1],new Set()).get(m[1])).add(f);
    for(const block of s.matchAll(/const groups=\{([^;]*)\};/g))for(const m of block[1].matchAll(/\w+:\['[^']*','([^']+)'\]/g))(names.get(m[1])||names.set(m[1],new Set()).get(m[1])).add(f+'(groups)');
  }
  const cards=pool.filter(c=>codesOf.has(c.id));
  for(const [name,files] of [...names].sort()){
    const M=cards.filter(c=>X.series(c,name));if(!M.length)continue;
    const cand=new Set(M.flatMap(c=>codesOf.get(c.id).flatMap(s=>[s,s&0xfff])));
    let best=null;for(const code of cand){const T=cards.filter(c=>has(c,code));const inter=M.filter(c=>has(c,code)).length;const j=inter/(M.length+T.length-inter);if(!best||j>best.j)best={code,j,T};}
    if(!best||best.j<0.4)continue;
    const fn=best.T.filter(c=>!X.series(c,name)),fp=M.filter(c=>!has(c,best.code));
    if(fn.length||fp.length)console.log(`${name} → 0x${best.code.toString(16)}（重合 ${best.j.toFixed(2)}）漏认 ${fn.length}，误认 ${fp.length}｜${[...files].join(',')}\n    漏认：${fn.slice(0,6).map(c=>c.officialName).join('；')}\n    误认：${fp.slice(0,6).map(c=>c.officialName).join('；')}`);
  }
}
process.exitCode=failures?1:0;
