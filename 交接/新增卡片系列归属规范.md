# 新增卡片系列归属规范

更新：2026-09-27，系列码统一入口已完成。适用于 2015 年及以后年度批次、复用旧身份、衍生物与任何系列支援效果。

事故分析及历史方案见 [系列本家识别问题修复方案](../系列本家识别问题修复方案.md)；最终实现与验证见 [系列归属说明](../docs/archetypes.md)。

## 1. 唯一真值与入口

以 data/locales/source-manifest.json 固定的日文 CDB datas.setcode 为准。同步脚本使用 BigInt 拆分四个 16 位码，只有自身码为空时才按 alias 回退。运行时通过 D.inArchetype(card,key) 查询；年份公共 series / arch 委托同一入口。

卡片数据的 setcodes: [] 表示权威的“无系列”，不能按英文名兜底。全部正式身份目前都有系列码数据，包含 85 种衍生物。确实没有数据库身份的未来自制卡，才可使用登记项中明确的英文名兜底。

系列登记在 data/archetypes.json，必须区分 setcode、name-fragment 和 race。卡名片段、种族分类须写清原因，不能伪造系列码。代码里的新名称必须登记；未知名称会被测试拦截。具体文件、数据流和加载顺序见实现说明。

## 2. 卡名、系列、主题分类分别使用

- 卡面指定具体卡名时，用 id / nameId、is、cardNameId 等现有精确卡名接口；别画和规则同名仍由身份系统处理。
- 指定系列时，用 D.inArchetype 或公共 series / arch。卡种、种族、等级、调整与所在区域等限制必须另外写全。
- family / families / isFamily 用于图鉴与卡组主题分类，不作规则依据。“废品／同调士”“希望皇／拟声”“艾克佐迪亚／竹光”可以作为合并筛选，但不能因此互认规则系列。
- 素材元数据中的 family、tunerFamily、tributeFamily、rankUpFamily、series、nameIncludes 等经统一规则入口判定；不允许靠手写成员 ID 列表模拟系列。

两个例子：侵略之炎有 Infestation 系列码，但仍是怪兽，不能被只检索该系列魔法／陷阱的入魔龙祖检索；世代之力同样只能检索“超量”魔法／陷阱。明确的排除条件不能被系列码覆盖，例如守护者检索卡面明列的五张例外。

## 3. 新增或复用卡片的步骤

1. 导入年度快照，保存可离线重建的原始供应方响应和来源清单。
2. 运行 npm run locales:sync，生成本年 setcodes 和语言资料。不要手改生成的 card-locales.js 或 archetype-data.js。
3. 在 data/archetypes.json 登记新增的所有系列名；卡名片段写明匹配方式与原因。别在单个分册中补 family、families、series 来绕过数据库；通用兼容标签只由公共代码生成，现有年度分组表可保留显示标签。
4. 如新增衍生物，用固定 CDB 的准确身份。旧显示名与数据库不一致时，在 data/archetype-token-identities.json 写明运行时 ID、真实卡密、数据库名称和生成卡密；这是身份对应，不是归属覆盖。新增真正自制卡须同时说明无数据库身份的原因和兜底规则。
5. 复用旧卡时检查 chronicle-costs.js 的 reused 表，保留一套等价处理，避免重复触发。用旧支援与本年新成员的实际对局测试确认兼容。
6. 对本年新支援与旧成员也写实际结果测试。至少覆盖实际进入手牌／场上、攻击力、素材合法性等结果，不能只断言“出现可发动按钮”。

## 4. 提交前验证

运行 npm run test:archetypes、npm test、本年逐卡扫描、chronicle-simulation、相关浏览器检查。重建正式 index.html，PVP 部署需重启服务，确保服务器与离线页面加载相同资料。

系列专项包含：

- 16 种旧系列兼容标签与固定 CDB 双向对照。
- 全部登记系列在整个运行时卡池的双向对照；全部身份必须有权威数据。
- 四段有符号 BigInt、alias 回退与权威空数组。
- Acorn 扫描所有源码中的 series / arch / inArchetype、分组表以及运行时素材元数据；未登记名称与规则中的直接 family 比较失败。
- 跨年份正例与误认反例、真实检索／特召／融合／战斗、衍生物身份与数值验证。

每批交接写明新增系列、来源、例外（如有）、跨代测试、构建和验证结果。全库扫描通过只证明这些断言与资料一致，不代替官方裁定认证；本作适配继续逐卡写入 implementationNote。

## 5. 当前例外与防回归边界

当前正式身份无系列码覆盖例外，也无缺失数据。八个卡名片段和一个种族分类列在登记表中，是明确分类，不是用来跳过守卫测试的白名单。

不允许为了通过测试排除一张错误归属的卡。先核对身份、子系列位掩码、卡名条件与卡种限制；确有本作有意偏离的规则，必须同时记录证据、implementationNote 和单独的实际结果测试。

旧存档结构不受静态系列码影响；旧录像若保存了修复前非法检索，重放可能在该动作停止。修复或加入新系列不能通过放宽全局合法性校验来维持旧错误。
