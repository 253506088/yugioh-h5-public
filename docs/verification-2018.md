## 整局与赛事方法

46 场年度整局使用正式五套预设，与 2016 青眼／十二兽分别交换先后手，再覆盖全部 26 条天命。每场第 24 个动作后进行 JSON 恢复，终局后从初始状态逐步重放并比较完整快照。

赛事使用固定种子 `20181001`、原 64 人名单、standard 难度和原行动／回合上限。最终验收的测试辅助器用 Node Worker 并行运行独立场次，每场仍调用生产代码 `Tournament.stepMatch`；主线程按原轮次屏障、种子和晋级树推进，不改胜负规则。每场在返回结果前完成完整重放，最后再恢复整个已完成赛事存档。

开发阶段曾先跑过一份串行赛事。最后修订改变了部分新卡的选择时序，旧开发态录像复核失败，因此没有把它当成最终证据；最终重新运行上述全部 63 场，逐局重放通过。没有放宽重放或保护判定断言。

## 重现

本机默认 `node` 为 14，执行验证使用已有的 `C:\nvm\v22.17.0\node.exe`。可先将该目录放到当前 PowerShell 的 PATH 前端，再运行 package scripts：

```powershell
$env:Path = 'C:\nvm\v22.17.0;' + $env:Path
npm.cmd test
npm.cmd run test:2018
$env:DUEL_YEAR = '2018'
node --test tests/chronicle-sweep.test.cjs
Remove-Item Env:DUEL_YEAR
npm.cmd run test:2018:simulation
npm.cmd run test:2018:tournament
node tests/chronicle-simulation.cjs --quick
npm.cmd run build
npm.cmd run test:2018:browser
npm.cmd run test:2017:browser
node scripts/build.mjs --out output/rollout-2018/rebuild/index.html
```

年度整局也可用 `DUEL_SHARD=0..3` 分成四份，配对和种子保持不变。正式来源、源码、测试和覆盖表均提交；日志和本机审核汇总不作为离线构建输入。
