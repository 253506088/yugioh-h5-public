# 根据描述联网组卡

2026-09-23 已增加黑话规范化、多主题分开构筑、文本请求自动进入检索，以及可核验的 2010 世界冠军原牌表。详见 [优化问题 2](optimization-2.md)。

入口是「组卡工坊 → AI 导入 → 联网组卡」。描述主题、喜欢的玩法、难度和年份等要求，选择「根据需求调整为可用卡组」或「推荐原版牌表，由我修改」，再点击「搜索并组建」。

此功能真实请求 **YGOPRODeck 的公开牌组搜索**，读取作者、原帖地址、牌表与说明；历史冠军路径读取并核验 **Road of the King** 赛事页和原牌表图。普通检索范围是公开牌组资料，不是通用全网搜索；其他网站仍可使用已有「网址」导入，未来可按适配器接口增加站点。模型不需要自带联网工具或额外搜索密钥。

## 如何工作

1. 模型把需求转换为最多三个简短英文牌组/系列关键词和赛制条件，并提取描述中的卡片截止年份。
2. 服务器访问 YGOPRODeck 公开网页实际使用的 `api/decks/getDecks.php`，每条查询最多读取 16 条数据，轮流合并各查询的结果，去重后保留最多 12 份，避免宽泛查询挤掉精确查询。记录实际检索条件、状态与时间；不把模型令牌发送到牌组网站。
3. 浏览器将真实来源密码交给已有三语名录与密码匹配器，处理别画、未收录、待实现、未知身份；核对本作卡池和截止年份。最多选择八份来源，按可用比例排序供模型参考。
4. 原版推荐模式让模型从实际来源中挑选；调整模式只向模型提供来源中**已实现、符合年份的卡片候选**及其类型、等级、调整属性和本地卡文摘要，不发送完整卡池。上下文超限时移除完整来源和对应候选，不截断 JSON。模型通常生成一副卡组，用户明确需要多套时最多两副。
5. 本地验证模型输出：每张卡必须属于实际送入上下文的候选，分区符合卡片类型，主卡 40–60、额外 ≤15、副卡 ≤15、主卡与额外同名 ≤3。来源对应关系由本地根据真实牌表生成，模型不能伪造来源 ID 或 URL。模型输出的玩法说明属于建议，不等于已模拟验证的连招或强度。
6. 构筑未通过时，把具体本地校验问题交给模型补正**最多一次**。少量总数偏差可再按真实来源数量做本地补齐并明确记录，最多六张且仍须通过全部候选/分区/主题校验。仍失败或没有推荐时，展示已抓取的原版牌表并注明未生成有效推荐。搜索失败/空结果时明确提示，不用模型记忆替代联网证据。

普通单目标通常有两次模型请求，快捷黑话规则省去规划调用，已核验冠军原版无需模型调用；多主题分开生成，每个构筑校验失败时最多补正一次。查询和来源读取各有截止时间，整个浏览器流程最长五分钟，可随时取消。没有搜索结果时不再调用构筑模型。

## 结果和限制

- 可展开来源列表查看作者、原帖、赛制、检索时间及本地可用比例，逐张卡也有可核对的来源链接。
- 「构筑调整」是模型建议；「与最接近来源的数量差异」由本地按实际卡片计数生成，独立于模型说明。
- 可直接查看任一已抓取的原牌表；此操作不再请求模型。原牌表保留未收录卡和原数量，仍走已有逐卡确认与工坊校验。
- 描述中的年份和手选年份同时存在时取较早者。限定年份时，没有 `releaseYear` 的手工卡不进入调整候选；不限制年份时仍可使用本作已实现的这些卡。
- 牌组发布于 2025 年并不表示用了 2025 年的卡：历史赛制重构以逐卡 `releaseYear` 判断。网页自报的价格、赛事成绩、强度不会被当作经过本项目核验的事实。
- 需求、推荐说明、来源地址、抓取时间和实际数量差异保存在草稿 `notes`，随卡组保存/导出保留；API 设置不会进入卡组。

## 部署与网络

需要 `npm start` 的本项目服务器。双击 HTML、GitHub Pages 和原静态预览会显示降级说明。模型调用仍可选浏览器直连或本项目代理；搜索由服务器完成。

`GET /api/ai/info` 会返回 `deckSearch: true` 和 `searchProvider: "YGOPRODeck"`。`POST /api/ai/search-decks` 只接受 `queries: [{query, format}]`，格式为 `any / edison / goat / casual / ocg / tcg`；请求不能改变搜索主机。复用现有同源限制、每 IP 限流、并发限制和请求体上限。

网络代码已从 `server/ai-proxy.mjs` 提取为 `server/ai-network.mjs`，旧导出保持兼容。搜索、网页抓取和模型代理都坚持公网地址校验与 TLS 连接地址固定。部分 TUN 代理把域名解析为 `198.18.0.0/15` 虚拟地址：此时仅将域名发送至固定的 Cloudflare HTTPS DNS，再校验真实公网 A 记录并固定连接，**不连接虚拟地址、不放行私网**。普通私网/回环解析和直接填写的保留 IP 仍被拒绝。DNS 失败时停止该请求。

## 开发入口与验证

| 文件 | 职责 |
| --- | --- |
| `server/deck-search.mjs` | 固定站点检索、数量/密码格式检查、来源地址生成、去重和部分失败处理 |
| `server/ai-network.mjs` | 公网 DNS、TUN 环境兼容、固定地址 TLS、响应限制与网页抽取 |
| `src/deck-research.js` | 规划/推荐/构筑 Schema、本地候选、上下文预算、来源校验、数量校验和差异计算 |
| `src/ai-provider.js` | 三种接口复用 plan/rank/build 操作，不依赖供应商搜索工具 |
| `src/ai-import-ui.js`、CSS、三语词条 | 描述输入、模式、年份、四阶段进度、来源证据与回退 |

```powershell
npm.cmd run build
npm.cmd run test:deck-research
npm.cmd run test:ai-import
npm.cmd test
```

自动化测试全部使用假上游或本地服务器，覆盖真实请求拼装、来源/卡片伪造拒绝、补正上限、空结果、服务失败、取消、保存/导出与三语手机布局。真实试验用 DeepSeek Flash 与公开搜索取得青眼牌表；一版 38 张主卡被拒绝，补正版本为 40 主卡 + 11 额外，逐卡均有来源且通过本地构筑校验。原始试验、报告和截图只保留在 `output/ai-research/`，没有真实密钥入库。
