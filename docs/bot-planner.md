# 机器人推演层：局面价值、回合推演、战斗推演与响应门

本批对应 2026-09-22「按你的理解优化机器人出牌，不做限制」。在原有「规则评分 + 边际收益 + 战术层」之上新增第四层 `src/ai-planner.js`（`DuelAIPlanner`），把[机器人出牌逻辑解析](bot-decision-logic.md)"可能的改进方向"里的第 2、3、4 条一次做完。规则引擎没有任何改动：`act()` 仍接受玩家的任何合法操作，改动只影响机器人的选择。

## 一句话结论

机器人现在**用一个统一的局面价值函数给"发动／召唤／进战斗／结束回合"打分**，每个候选都在引擎副本上真实执行、再让旧策略把本回合走完（含战斗阶段），比较结束时的局面；战斗阶段每次攻击也先在副本上结算再决定；对方连锁窗口里的响应要证明"发动后比不发动更好"才发动。同一随机种子下决定仍然完全可复现，推演不消耗实局随机序列。

## 各层关系

```
aiNext()
  ├─ pending → chooseAI（响应评分末尾接 DuelAIPlanner.responseGate）
  ├─ DuelAITactics.battlePlan  公开场面能直接打死 → 直接走
  ├─ 战斗阶段 → DuelAIPlanner.battle   逐次攻击推演；否则退回贪心
  └─ 主阶段  → actionScore 排序
                └─ DuelAIPlanner.select
                     ├─ DuelAITactics.evaluate  保留：场面保留／不赌抽卡
                     ├─ DuelAIMarginal.action   保留：重复发动与替代目标
                     └─ rollout ×（≤4 候选 + 进入战斗）→ positionValue
```

`casual` 难度不启用推演层，保持原来的贪心策略，作为"休闲"对手。

## 局面价值 `positionValue(e, owner)`

与阶段无关的静态估值，双方对称，`WIN = 1e6` 表示已判胜负：

| 项 | 计算 |
| --- | --- |
| 怪兽 | 每只 250 + max(ATK, DEF×0.8)×0.6 + min×0.08 + 场上速攻能力×250；对方里侧一律按 **500/1600**，与推演器脱敏用的替身一致 |
| 最高攻 | 己方攻击表示最高 ATK×0.55 |
| 手牌 | 己方 +180／张，对方 −120／张 |
| 后场 | 己方表侧生效 +300、里侧 +200；对方每张 −160 |
| LP | 己方 ×0.35，对方 ×0.40 |
| 战斗威胁 | 对方最强攻击者打得过的己方怪兽按价值×0.35 扣除；己方最强对对方同理×0.85 加回 |
| 下回合伤害 | `expectedDamage`：会致死 −4500 再 −0.2/点，否则 −0.3/点；己方能造成的 +0.2/点，能致死 +1500 |
| 手牌上限 | 超出每张 −180 |
| 卡组 | 己方 ≤2 张每张 −1500；对方 ≤2 张每张 +600 |

己方 LP 权重高于"可能避免的伤害"，所以推演里被打掉的 LP 比"下回合可能挨打"更重：这一点让机器人不再为了少召唤一只怪而白挨 1700 点。

## 回合推演 `rollout(e, action, owner)`

1. 用 `DuelAIMarginal.project` 在副本上执行 `action`（对方手牌／卡组／里侧卡脱敏、随机与抽卡标记为不确定）。
2. 继续让副本的 `aiNext()`（旧策略，不递归推演）走最多 **2 步**主阶段动作。
3. 之后如果还能进战斗，就进入战斗阶段并按同一套攻击策略把攻击打完；这样"先展开再打"与"直接打"在同一尺度上比较。
4. 遇到抽卡就停在抽卡前，按每张 **190** 计入价值。
5. 每次 `aiNext()` 最多 **30** 次投影，超预算的候选返回 `null`，回退到基础评分。

`select()` 取基础评分前 4 个通过战术层过滤的候选；通常召唤的另一种表示（攻击／盖放）总会一起比较。最终分 = 基础分×0.5 + clamp(±2500, 推演价值 − 当前价值)×0.6，能直接取胜 +5000、会落败 −5000。只有当每个候选都比"直接进战斗"更差 150 以上时，机器人才什么都不做。

## 战斗推演 `battle(e)`

每只可攻击怪兽的每个合法目标（含直接攻击）先按静态收益排序取前 10 个，逐个在副本上结算，收益 = 结算后价值 − 当前价值；对方每张里侧魔陷扣 60 + ATK×0.04（最多 3 张）。收益 ≤ 0 的攻击不宣言。能同时达到相同结果时，**先用弱的怪兽**，把最强的留给后面的直接攻击。取胜的攻击立即执行。

验证过的判断：

| 场景 | 决定 |
| --- | --- |
| 栗子球面对里侧 1600 守备墙 | 不攻击，进入主要阶段 2 |
| 青眼面对栗子球、对方三张盖卡 | 仍然攻击 |
| 对方 1500 LP，己方牛头人 + 栗子球，对方两张盖卡 | 先用栗子球直击，再用牛头人收尾 |
| 青眼 + 牛头人 vs 守备栗子球、对方 3000 LP | 牛头人清守备怪，青眼直击取胜 |
| 牛头人对牛头人的 1 换 1 | 不攻击 |

## 响应门 `responseGate`

在 `aiResponse`／`aiScore`／边际收益／战术门之后再做一次"放弃 vs 发动"的局面比较：

- 发动后落败而放弃不落败 → 不发动；发动能直接取胜 → 强烈偏向；放弃会落败 → 偏向发动。
- 没写 `aiResponse` 的默认分响应（对方连锁时 200 分）必须让局面**变好**才发动：陷阱封印不再在对方开局的空窗口发动，而会等到对方发动圣防时。
- 作者写了 `aiResponse` 的响应保留原时机，除非发动后局面反而差了 700 以上（守护圣兵这类只改攻击目标的效果不会被误杀）。
- 需要代价的反击陷阱仍由 `negationWorth` 单独裁定。

## 顺带修正

- **波动加农炮**（Wave-Motion Cannon）此前注册成快速效果，机器人在对方连锁上反复发动，与马头鬼 LV8 的无效互相连锁 49 次。改为主阶段起动效果（速度 1）。
- 推演副本跳过 `snapshot()` 深拷贝与 `assertState()` 校验（失败的副本直接丢弃）；`ai-marginal.js` 的 `cp` 改为手写深拷贝，比 `JSON.parse(JSON.stringify)` 快 5 倍；`fieldValue` 用 `byCard` 索引代替全表过滤。单次投影从 30 ms 降到约 2～4 ms。
- 里侧对方怪兽在推演里从 Battle Ox（1700/1000）改为 500/1600 的通常怪兽，避免把每张盖怪都当成能反打的攻击手。

## 耗时

标准难度下主阶段一次决策平均约 280 ms、最长约 450 ms（18 核桌面机）；战斗阶段约 30～60 ms；响应约 10～20 ms。UI 观战快速模式每步 160 ms 的定时器在决策完成后才排下一步，肉眼节奏与以前接近；竞技场 `turbo` 每帧 12 ms 预算会少跑几步，无界面跑完一场 64 人赛事约需 12～14 分钟（此前约 5 分钟），2009—2013 年代 170 场模拟约 25 分钟（此前约 12 分钟）。

## 效果验证

镜像对局：同一卡组、同一种子、同一先后手，各打两局，一局 0 号座位用推演层、另一局 1 号座位用，另一座位用原策略。43 套预设各 2 个对手：

| 指标 | 结果 |
| --- | --- |
| 总局数 | 168（84 对镜像） |
| 推演层胜率 | 60.1%（101/168） |
| 两局都赢 | 22 对 |
| 两局都输 | 5 对 |
| 异常／未完成 | 0 |

两局都输的对局多是先手展开被对方一回合打穿（无论谁执子都输的牌序），以及对方"炸场后大怪"的组合牌；推演深度只有本回合，仍看不到对方下回合的展开。

回归：`npm test` 全量检查、`tests/ai-planner.test.cjs` 12 项新增检查，以及三套长模拟（年度、2009—2013 年代、64 人赛事两个种子）均通过，无非法动作、无卡死、录像可重放。

## 仍然没有做的

- 不预测对方回合的展开，只用公开场面估计对方下回合的攻击。
- 推演里对方永远 pass，"发动后的局面"是无干扰前提。
- 默认分仍是名单／常数驱动；推演层只重排前 4 个候选，基础评分为 −100 的动作（例如速攻魔法在自己回合盖放）不会被考虑。
- 局面价值的系数是手调的，没有按卡组校准。
