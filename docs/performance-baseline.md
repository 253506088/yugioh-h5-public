# 性能基线与验收口径

测试脚本：`scripts/measure-performance.cjs`。浏览器为本机无头 Edge，通过 CDP 设置 CPU 降速；手机档为 360×800、CPU 4 倍降速，不等同于真机。脚本记录 PerformanceObserver 的 LCP、长任务、资源字节和可交互时间，并保存首页／决斗截图。原始报告在 `output/performance/`，未纳入 Git。

基线是10月18日保留的 `b02449c` 根 HTML 测量；最终 web 样本是10月20日完整交付验证中新执行的测量。以下为单次冷启动样本，不是多次平均，也未进行真实移动网络限速。旧基线不是本次重新执行。

| 指标 | 改动前单文件 | 最终 web |
|---|---:|---:|
| HTML 文件大小 | 90,384,172 B | 17,639 B |
| 桌面首页可交互 | 4,694 ms | 232 ms |
| 桌面首页长任务数 | 6 | 1 |
| 桌面首页累计阻塞（每项减去 50ms） | 3,742 ms | 56 ms |

最终 web 的桌面首次进入决斗约 4.47 秒（从导航起算，包含截图与点击等待），手机 CPU4 约 22.29 秒。首页的改善不能掩盖这部分仍有明显加载成本。当前没有完成按对局卡片的依赖闭包加载，完整规则注册仍需要全部年份数据。

最终 web 首页记录到含 HTML 在内的编码资源约 183KB。原版通过 file:// 读取，新版通过本机 HTTP 和压缩传输；这不是同一网络条件的下载对比。原始基线在 `output/performance/release-2026-10-18T03-54-11-474Z/` 对应日志及当时报告；本次最终测量、LCP和截图在 `output/performance/release-2026-10-20T06-05-27-753Z/performance/`。较早的 `baseline-painted/`、`web-painted/` 是历史测量工作目录，不能替代本次带时间戳的成品证据。

所有 web JS 文件在构建时限制小于 2MiB；HTML、首屏脚本、CSS、首页三张图分开传输，媒体按使用位置加载。详细尺寸、压缩大小、内容哈希和资源清单见 `output/build-web-report.json`。Brotli/gzip 和缓存策略有本地 HTTP 断言。

四场并行的 8 人赛事本次测得 7 场、578 次操作，全部完成并逐操作重放一致；界面观察到 3 个长任务，最大 95ms、累计阻塞 48ms，包含赛事初次建盘和界面更新。不能据此声称稳定达到零长任务或真机 55–60fps。AI 推演已移到 Worker，剩余主线程工作主要是建盘、局面传输、翻译和渲染。赛事采用软时间预算，操作数会随开局和实际预算变化，准确重播依靠保存的操作与随机状态。

本轮新增验证覆盖：web 懒启动、真实卡图请求、大卡面和抽屉、手机即时详情、三语按需加载、初局／重赛猜拳、Worker 单步与 RNG、整局录像一致性、四场并行暂停与重放、P2P 双会话和 ICE restart、轮盘补掷与不重复掷骰、机壳陷阱检索、压缩与私有路径阻断。

后续性能工作应优先解决首次进入游戏的数据量，以及渲染、翻译的剩余长任务；用同一脚本在独立空闲浏览器中重复采样，再用真实中端手机和限速网络验收。禁止将首页数字写成整个应用所有操作均小于 1.5 秒。
