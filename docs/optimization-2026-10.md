# 2026-10 加载、决斗盘与联机优化

本轮落实自 [优化方案](../交接/优化方案2026-10-17.md)。卡池仍为 13,526 个目录身份、8,185 个可对战身份、148 套预设，没有借优化扩大年度完成口径。

## 使用与部署

```sh
npm ci
npm run build:web
npm start
```

网页发布目录是 `dist/web/`。服务器优先使用这个目录，Docker 也在构建阶段生成它；通用静态托管可直接上传该目录的内容，子路径部署使用相对资源地址。不要把仓库根目录的离线 HTML 当作 web 优化包上传。

`npm run build:single`（兼容原 `npm run build`）仍生成根 `index.html`，可以直接双击，保留内嵌卡图、卡框和已有本机配乐。没有本机音频缓存时，两种构建都沿用清单中的在线音频回退。单文件中的 Worker 代码也已内嵌，不依赖旁边的脚本文件。

两种构建共用 `scripts/lib/script-files.mjs`，生成后都检查脚本语法。web 输出包括带内容哈希的脚本、年份 JSON、语言 JSON、卡图、卡框和音频。工坊及 AI 导入、赛事、服务器联机、P2P 独立加载；卡查打开时补齐其他语言说明，保留跨语言搜索。Node 服务按请求协商 Brotli/gzip，尊重 `q=0`；哈希资源使用一年 immutable 缓存，HTML 使用 no-cache 和 ETag。页面只预加载第一段基础代码，不执行整个规则库。

web 构建保留代码标识符和语法，仅压缩空白。部分既有规则通过函数源码识别检索、融合或代价行为，不能直接启用变量名压缩；这会改变效果登记，即使基础页面还能打开。`npm run test:web:runtime` 会重建并逐项比较全部卡片与效果登记，保证 web／Worker 和正式引擎一致。卡名翻译使用共享前缀的字面匹配器，效果复制使用原始登记索引，减少启动时重复扫描；完整卡名及跨年复制登记有等价性回归。

**当前边界**：首页已与规则库分离，但第一次进入游戏仍加载全部年份的规则数据和当前语言的说明。年份文件已经拆分，尚未实现“只加载本局所需卡片”的依赖闭包；全局效果注册还依赖完整目录。不能把本轮称为已经达到“首次进入决斗只需 1–2 MB”。实测和剩余性能目标见 [性能基线](performance-baseline.md)。

## 决斗盘

- 桌面标准档在 1920×1080 下使用约 100px 宽的普通／额外怪兽区卡位和约 100px 的可视手牌（手牌控件 104px）。设置提供紧凑／标准／大卡面，低高度屏幕有紧凑下限；手动大卡面允许纵向滚动。
- 回合、比赛、联机、赛事与法则信息移动到同一个顶栏容器，保留原节点和事件。右侧面板收为窄栏，按钮、`\` 快捷键可展开，遮罩或 Esc 收起；偏好会保存。窄屏使用原有布局。
- 点击卡片立即显示属性、数值、灵摆说明和完整卡文，操作按钮同时可用。桌面悬停延迟 120ms 显示说明；手机使用底部面板。对手未公开的手牌、盖牌仍不显示身份或说明。
- 保留未变化的场区、手牌及头像 DOM；日志按条目增量更新。粒子节点复用，特效层限制并发；手机主要面板关闭背景模糊，星空在隐藏页面、非首页或减少动态效果时停止调度。

日志同时校验编号与内容：重赛、换局和录像跳转复用编号时，会替换旧内容并按当前顺序排列，不保留上一局的记录。

## 机器人与录像

人机决策和赛事推进在 Worker 内执行；页面收到操作或局面更新后再渲染。页面切换、换局和恢复存档会丢弃过期结果，取消的 Worker 不得写回新对局。

普通观战先在 Worker 中算完整局，记录每次操作前的随机状态，并每 40 步保存快照。页面回放不重新运行 AI，提供暂停、单步、进度跳转和约 700／300／120ms 的三档速度。桌面工具栏可以导出完整录像 JSON。计算超过 2,400 步或出现非法操作时显示错误并保留原对局，不伪造胜负。

Worker 人机、普通观战和实时赛事的可选前瞻／公开战斗搜索采用约 8ms 软预算；合法性、基础战术筛选和强制选择仍完整执行，不能据此承诺每次 AI 调用都小于8ms。既有 Node 确定性工具保留固定次数预算；赛事种子决定开局，操作录像用于精确重播。恢复普通观战存档时，会从保存的位置重新计算后续录像；完整录像导出文件用于保留该次预计算结果。

赛事仍支持 2–64 人和默认四场同时推进，保留既有调度档位。Worker 持有运行中的引擎，只复制并回传改变过的场次，不再为每次更新复制全部历史录像；turbo 批量计算后回传。空闲的人机 Worker 保留已经加载的规则数据，换局时不重复加载；有未完成任务或错误时才终止并重建。暂停、修改配置和换赛事期间迟到的更新会被丢弃；原来的独立赛事存档和完整导出保持可用。

## 开局与规则修复

新建人机局、工坊开局、首次进入和重赛都由玩家实际出拳，平局重猜；场外不再提供先后手选项。首页的示例局不写入正式存档；已保存的对局直接恢复。BO3 第一局猜拳，局间继续使用既有比赛规则；已有服务器联机的先手规则保持不变。

命运轮盘2跳过主要阶段2时，在结束阶段效果与手牌上限检查之前补掷。已经进入主要阶段2并掷过时不再补掷；状态和队列支持 JSON 恢复与 AI 克隆。

卡文审计覆盖全部目录并输出 28 个跨年样本，未发现缺文、明显跨语言回退或灵摆分段残留。“机壳工具 丑恶”的系统启动文字是通常怪兽描述，800LP 检索属于单独的灵摆效果段。另修正该检索处理器，使它能检索属于机壳系列的魔法／陷阱，不再仅接受怪兽和牲祭。

`npm run cards:audit-texts` 是只读启发式审计，不是官方裁定认证。人工修正文案可填写 `data/locales/overrides.json`，必须提供卡片、语言、来源、日期和理由，再执行 `locales:sync`。本轮覆盖表为空，固定 CDB 来源未更新。

## P2P 好友对战

从首页选择“P2P · 好友直连”。双方先选卡组，房主生成邀请，来宾粘贴后生成应答，再由房主粘贴应答。连接成功后双方出拳，通过提交摘要再公开出手的流程决定先攻。传输使用加密的 WebRTC DataChannel，不需要游戏服务器。

这是房主主持的 BO1 经典规则好友局。房主运行完整引擎，可以看到完整状态，因此只适合互相信任的朋友。来宾仅收到脱敏视图；它和现有服务端共用 `pvp-public.js`、`pvp-projection.js`、`pvp-intent.js`，每个局面使用新的不透明卡片引用，拒绝过期版本、越权座位和非合法操作。传输有分片、长度限制和请求确认。

跨网络时默认使用公共 STUN 发现地址；同一局域网可取消该选项。没有配置 TURN 中继，对称 NAT 等网络可能无法直连，可改用已有服务器模式。房主可生成 ICE 重连邀请，重新交换文本后继续同一局。双方页面必须保持打开，刷新或关闭房主页面不提供服务器式持久恢复。双方版本指纹必须一致。

猜拳消息按顺序完成摘要校验后才应用后续局面，避免异步校验导致来宾漏掉开局。平局重猜、双方确认再战和重连均有双会话回归。未开局或对局结束后可从连接页面直接切换服务器模式；进行中的对局需先结束或断开。

本轮验证的是本机两个独立浏览器会话的真实连接、隐私、操作同步、过期操作拒绝和手动 ICE restart；未把它称为跨公网 NAT 的实测结果。现有服务器 BO1／BO3、计时、SQLite 和断线恢复继续保留。

## 产物保留

普通构建不再无条件把大型 HTML 复制到 `output/v4-builds/`。需要保存发布快照时使用 `npm run build:archive`。原有历史构建、下载原件、研究、截图、失败现场和 `output/rollout-2025/` 全部保留，没有清理旧文件或改写 Git 历史。

`dist/` 和 `output/` 是忽略的本机产物；正式源码、压缩卡图、来源、固定三语 CDB、人工覆盖表及根 `index.html` 继续跟踪。磁盘不会因为本轮自动缩减到数 GB，收益是停止默认构建不断复制约 90MB 的页面。

## 复现验证

`npm run verify:optimization` 使用当前 Node 重建两种产物，然后执行全量规则、构建登记一致性、单文件页面、web／Worker／P2P、服务器兼容、20场模拟和轮盘补掷整局，最后测量性能并独立重建核对哈希。需要 Node 22.13+ 和可用的 Playwright 浏览器；本机使用 `C:/nvm/v22.17.0/node.exe`，可用 `DUEL_BROWSER` 指定浏览器路径。

每次运行保存在新的 `output/performance/release-<时间>/`。仅在完整范围全部通过且源码指纹未变时更新 `release-verified.json`。开发时可用 `-- --only=web,p2p` 选择专项，该结果会注明范围，不覆盖完整交付记录。历史研究与失败现场持续保留。
