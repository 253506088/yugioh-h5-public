# 副卡组、BO3 与卡组工坊

2026-09-30。设计审查与取舍见 [正式实施设计](side-deck-match-design.md)，实际验证见 [验收记录](verification-side-matches.md)。本次没有扩大 2016 卡片实现范围。

## 构筑与工坊

桌面左侧是卡片详情，中央是当前主卡／额外／副卡的独立副本矩阵，右侧是可搜索牌库。工坊铺满窗口，名称与排序位于顶部，卡片下方没有操作按钮。保留系列、年代、类型、仅可用／仅已编入、分页、卡片完整说明、复制、备注与撤销重做。手机默认打开当前构筑，通过顶部页签切换牌库，长按可拖拽。详见[拖拽重排说明](workshop-drag.md)。

从牌库卡图拖入主卡、额外或副卡区可新增；构筑分区之间拖动可移动，拖回牌库或点击右上角×可删除，区内拖动可排序。顶部各分区标签也是拖入目标。每张副本包含来源分区和下标，不会误删另一区的同名卡；拖拽、排序和删除均可撤销。没有常驻的合法性提示或先选择再应用的步骤。

有效出战构筑要求主卡40–60、额外0–15、副卡0–15；三个分区合计同名最多3张。副卡可含主卡与额外怪兽，出战时仍须符合自然分区。沿用本作无赛事禁限表的规则。编辑、保存、导出允许不完整草稿；开始游戏前检查双方卡组，非法时不能开始。换备也允许临时缺卡或超限的草稿，确认准备时才采用最终合法构筑。

JSON v3 完整导出三分区和备注；文本、JSON、YDK、YDKe、AI 识别结果均可载入副卡。超限牌表保留为可修复草稿，未确认／未收录／未实现卡仍进入备注。YDK / YDKe 本次提供导入，导出使用完整 JSON，不给没有外部密码的本作卡制造错误编号。

三套2016年度牌组各15张原表副卡已全部接通。生成器加载真实效果模块后才判断可用状态，来源数据仍保留在 data/decks-*.json；[副卡可用性报告](side-deck-availability.json)列明各表数量和排除项。其他没有来源副卡的预设可用空副卡参加BO3。

## PVE / PVP 比赛

开局设置或联机大厅选择BO1／BO3。BO1为默认；BO3先取得两局胜利结束，平局不加胜场并补赛，连续三平结束为整场平局。界面显示真实局号，不限制只能进行三局。经典规则和天命法则均可组合；每局重建引擎、重置LP与行动计时、重新抽取法则，副卡不会进入引擎实体卡、抽卡或检索区。

败者选择下一局先后攻，平局沿用上局；随后进入换备。每轮基于上一局采用的构筑编辑，全部内部卡片ID及其数量必须与首局报名完全一致。可以改变各分区张数，但不能从牌库临时加卡或删除报名卡。准备后锁定；保存卡组不会因比赛换备被覆盖。比赛结束可把PVE最终构筑另存为卡组。

PVE局间不限时，刷新恢复比分、阶段和已应用的换备草稿。机器人仅根据上一局逐事件记录的公开卡片作保守换备：当前优先从既有副卡中换入针对后场／怪兽的通用处理，最多两张一换一，保护系列及仪式／融合组件；无收益或没有副卡时保持构筑。规划器不接受对方构筑、隐藏手牌或副卡输入。普通双机器人观战可选BO3，双方自动准备，点击“继续下一局”推进；机器人淘汰赛保持原有单局晋级、平局重赛和录像格式。

PVP选择先后攻30秒，换备120秒；超时默认败者先攻，未准备方使用上一局合法构筑，不采用未提交草稿。双方连接正常且均准备后才开始下一局。每人整场累计60秒重连额度；断线冻结行动与局间计时，重新连接不补满额度。服务器停机不消耗已落盘剩余时间。

“认输本局”计对方一局胜利；“放弃整场”直接结束比赛并保留实际比分。PVP断线超额判整场结束；双方均离线或系统保护属于中止，不伪造未进行的局数。PVE旧有games/wins仍是单局统计，新增matches/matchWins/matchDraws为整场统计，中止不算正常完赛。

比赛概览列出各局结果、先后攻、回合数，并可查看单局记录。PVE可导出包含比赛状态和每局快照的JSON备份；它不是旧版单局或赛事录像的导入格式。PVP历史日志通过服务器逐席位过滤，只能访问本场记录，不导出双方私密快照。

## 兼容与维护

- 卡组存储与草稿使用v3键，缺省side兼容为空；v2原键保留。非法条目提供诊断；后续保存前先保存原文恢复副本，工坊可导出恢复备份。存储空间不足不宣称保存成功。
- 本地对局存档仍保留原引擎快照根字段，新增可选match、matchDraft、matchArchives、matchOptions。旧快照按原单局恢复，新比赛恢复校验比分、局序、报名守恒和引擎开局构筑。损坏原文保留，明确提示后可从比赛概览导出。
- 关闭换备页只返回概览，不表示准备；已经完成的拖拽会保存为草稿，包括尚未满足最终张数的中间状态。去首页、工坊、赛事或PVP不会把本地比赛的比分与引擎拆开。
- PVP协议升级为2。局内动作绑定gameId/revision；局间绑定matchId/roundId和个人提交锁。事务提交成功后才确认；重复请求沿用回执。旧客户端需刷新，老房间数据保留BO1兼容。SQLite版本标记为2，拒绝未来未知版本。
- 对手只收到比分、局号、先攻与准备状态；本人构筑、报名清单和换备草稿只发给本人。历史日志按事件发生时的可见性记录；不能在终局后用完整卡组倒推公开信息。
- 新模块为src/deck-editor.js、match-core.js、match-ai.js、match-ui.js、workshop.css和i18n-matches.js。构筑规则仍以DuelDecks.analyze为入口；服务器与浏览器共用核心，不复制规则。
- 新功能不增加外部逻辑依赖，单文件HTML继续支持离线PVE、工坊与导入；PVP需要HTTP/WebSocket服务。

## 复现命令

需要Node≥22.13。本机使用C:\nvm\v22.17.0\node.exe；在PATH最前面加入对应目录后执行：

```text
npm run decks:chronicle
npm run test:matches
npm test
npm run test:matches:simulation
npm run build
npm run test:matches:browser
npm run test:browser
npm run test:ai-import:browser
npm run test:pvp:browser
```

仅提交正式源码、生成输入／输出、测试、说明、交接和根目录index.html。私人需求、截图、数据库、日志、模拟现场、性能报告与诊断脚本均留在需求文档/或output/，由.gitignore明确排除。
