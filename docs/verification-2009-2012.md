## 浏览器与性能

浏览器范围包括原有决斗／工坊／三语回归、分页与字号、小屏布局、连锁响应与音频、2003—2005与2006—2008年度回归、机器人收益判断、新四年筛选及竞技场。新年度检查实际点击全部十二套预设，核对双方构筑；在中英日间切换超量素材、表示与落位，保存后刷新；通过同一弹窗选取手牌同调素材。

桌面和390×844手机截图已人工查看，年度筛选在手机中占完整一行。原有体验测试还覆盖大字号、三语及多组横竖屏尺寸；十首音轨通过浏览器元数据解码和真实播放器行为检查。

卡池扩大后发现原有16人竞技场超过180秒检查时限。CPU采样定位到位置查询、持续无效检查与无关卡的重复求值后，进行了以下优化：

- `find()` 直接寻找卡片，并保存每次读取都会核对的区域位置提示；提示使用引擎独立的 WeakMap，不进入存档，不在推演副本间共享，也不保存卡片对象。
- 持续效果只为真正匹配的卡创建引用，重复名字查询缓存静态身份；装备、技能抽取及被动效果先匹配身份和用途，再做完整生效判定。
- 可用动作先排除区域、速度和复制目标不匹配的效果，随后仍通过原有完整合法性检查。

同一固定种子的废品对机壳前35步，CPU采样下决策耗时由 **31,420.7 ms → 3,348.0 ms**；电子龙对珠泪前35步由 **900.0 ms → 308.6 ms**。两组前后各自的动作与随机状态摘要完全一致。这是本机样例的观测值，不是所有设备和牌组的统一加速比例。竞技场继续使用原有180秒完成断言。
