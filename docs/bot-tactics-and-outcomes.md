# 机器人出牌克制、守备与胜负原因

本批对应 2026-09-13 的四项小优化。机器人规则在普通人机、双机器人观战和死斗竞技场中共用；规则引擎仍允许玩家自己执行合法操作。

设置底部增加「项目与署名」，显示 **不锈钢琴** 和完整仓库链接；主页可见页脚也提供署名与 GitHub 入口。地址为 `https://github.com/253506088/yugioh-h5-public`，在新标签页打开。署名不随语言切换，说明支持中、英、日三语。

## 出牌时机与场面保留

`src/ai-tactics.js` 在现有动作评分及 `src/ai-marginal.js` 的重复收益判断上增加以下决策：

1. **优先完成已知的致胜战斗。** 自己的主要阶段 1 和战斗阶段会检查公开场面。用克隆引擎实际结算攻击、攻击顺序和合法的守备转攻击操作；找到取胜路线后，先进入战斗／执行这次攻击。比如小怪先清除守备怪兽，留下大怪直接攻击。
2. **避免没有补偿的场面损失。** 评估可选发动、额外召唤和上级召唤造成的实际结果。场面已经占优时，显著损失己方怪兽而没有足够伤害、解场或其他补偿的操作，会让位给其他行动或结束阶段。可选连锁及同一时点的可选诱发也参与判断。
3. **保留有用展开。** 直接取胜的效果、劣势时的解场和有效升级继续可用；对于暂时降低场面价值的中间动作，最多再观察两次旧 AI 会选择的召唤／展开行动，避免一概禁止用素材换怪兽。
4. **保守处理未知抽卡。** 不靠预计能抽到的那张好卡替拆场找理由。发生抽卡时记录抽卡前的场面，按抽卡数量估计一般手牌收益，从而避开「把大怪全部除外，再赌两张新卡」之类操作。

战斗搜索最多 32 个展开节点、每个节点最多 8 个候选动作、路径最多 12 步；出牌筛选最多评估 8 个需要推演的动作。没有找到可确认的致胜路线时，继续用原有评分和本次的场面保留判断。它不是完整的多回合对弈搜索，也不保证对所有卡片组合都走出最优解。

对方未公开的手牌、卡组、里侧卡片在战术推演中做脱敏处理。公开场面上的致胜路线不代表排除了所有手坑；真实对局仍正常开放响应。例如战斗消失者可以在实际攻击时阻止该次取胜。

推演复制游戏状态与随机状态，清除上一次推演的函数包装，不把预测行动写进真实记录。AI 选择不消耗真实对局随机序列。赛事仍记录真实执行的动作并按动作重放。

## 防守表示

通常召唤阶段同时比较攻击召唤和**里侧守备盖放**。如果攻击表示会承受致命伤害，而盖放能避免该次伤害，就优先盖放；这不要求怪兽的 DEF 高于 ATK。反转效果怪兽也优先保留其盖放价值。

有有效登场收益、或攻击召唤能形成已知致胜战斗时，继续使用攻击表示。符合规则的旧怪兽在受到压制时也会考虑转成守备。此处没有增加规则不允许的「表侧守备通常召唤」。

防守判断估计对方公开场面的下一次攻击压力，不预测下一回合的未知抽卡、完整展开或每一种攻防连锁。

## 结束原因与兼容

`src/duel-outcome.js` 提供统一结束原因：

| 类型 | 显示内容 |
| --- | --- |
| `lp-zero` | 生命值归零 |
| `deck-out` | 无牌可抽 |
| `exodia` | 特殊胜利 · 艾克佐迪亚 |
| `special` | 其他卡片特殊胜利，并保留来源卡 |
| `draw` | 其他平局 |

`state.outcome` 保存胜方、败方、回合和具体原因，特殊胜利可带 `sourceId`；胜负日志同时保存一份独立副本。保留既有 `winner`、`resultReason` 与艾克佐迪亚动画识别。旧存档缺少 `outcome` 时，从原有结果推导显示，不要求重开一局。

卡组抽到 0 张本身不会落败；只有之后必须抽卡而抽不到时才判负。需要抽多张但只剩部分牌时，先记录已完成的抽卡，再记录无牌可抽的结束原因。重复结束调用及赛后抽卡／伤害不会覆盖已记录的结果。

普通人机与机器人观战的结算弹窗显示独立原因区块。决斗记录和导出记录保留明确原因。竞技场在当前直播／回放位置结束时显示原因提示；回退到结束之前会隐藏提示，播放进度条保留同一 DOM 节点。提示高度随语言、字体和窗口宽度变化，避免覆盖战场。
