# 决斗轨迹：原因记录与回合浏览

本轮对应用户要求：能够看出为什么扣生命值、是哪张卡让怪兽特殊召唤、为什么丢弃／送墓／除外，以及按回合选择记录。

## 使用方式

在战场点击「决斗记录」。窗口默认显示最近回合，记录按发生顺序排列。左侧回合目录和上方回合选择器可切换回合，也可以使用上一回合、下一回合、最新或全部回合。

事件可筛选为生命值、召唤、卡片去向、发动与战斗、阶段与结局；支持搜索卡名及原因，卡名检索兼容中、英、日名称。记录中的卡名可打开已有详情页，返回时保留回合、筛选、搜索和滚动位置。

每条记录由实际事件、原因、变化结果组成，例如：

- 因「死者苏生」的效果特殊召唤「青眼白龙」，显示「墓地 → 怪兽区」。
- 为发动「雷破」支付弃牌代价，将「牛头人」从手牌丢弃到墓地。
- 「青眼白龙」攻击「牛头人」，显示双方数值以及「LP 8,000 → 6,700」。
- 「噩梦之拷问室」等后续效果与最初触发事件分别记录来源；不会简单地把当前所有变化归给上一张发动的卡。

桌面保留回合目录和概览，小屏使用选择器，短横屏压缩概览以保证正文空间。短横屏原战场标题栏隐藏时，页头新增记录入口。窗口内正文滚动，回合控制与关闭／导出按钮保持可达。长记录分批显示，每次 100 条，可继续加载。

「导出全部记录」导出当前对局已经记录的全部内容，不受当前回合、事件类别或搜索条件限制。赛事回放导出的是当前播放进度之前的记录，不预先展示之后发生的行动。

## 引擎数据

`src/duel-log.js` 提供记录模型、格式化、回合分组和导出脱敏。`src/log-engine.js` 在公用结算接口捕获来源，不需要为每张卡手写展示文案。以下接口参与记录：

- 发动代价、效果结算、后续操作与延迟选择；
- 扣血、回复和 LP 支付，以及直接设置生命值的效果；
- 通常／上级召唤、特殊召唤、融合／同调／超量／连接／仪式／灵摆召唤；
- 卡片移动、弃牌、解放、素材使用、抽卡和检索。

日志仍保存在 `state.log`，以新到旧排列，避免破坏原侧栏读法；新窗口使用副本分组、按时间顺序展示。新增 `trace` 字段包含阶段、回合玩家、来源卡、效果键、连锁编号，以及本次操作适用的字段：LP 前后值、原区域、目的区域、区域所属玩家、使用素材、原定去向与替代去向等。

来源分为效果、发动代价、召唤、战斗和规则。延续任务保存 `traceCause`，但显式指定的来源优先；例如卖棺者追加伤害的来源是卖棺者，不是先前把怪兽送墓的雷击。连续效果、装备回复、诅咒扣血等直接回调补充了明确的来源参数。

直接赋值 LP 的效果也记录变化。记录器会扣除同一处理过程中已经通过伤害／回复／支付接口记录的变化，避免重复记账；判定结束前先补齐变化，再记录最终结果。

## 存档、回放与隐藏信息

新对局使用 `state.logVersion = 1`，完整保留日志，不再截为最近 100 条。旧记录未保存的来源、已经删掉的早期事件无法补回。正常继续旧存档时保留已有内容，之后追加新的详细记录；界面会提示早期记录可能不完整。

缺少 `logVersion` 的旧赛事录像按原日志格式和长度限制重放，不在恢复对象时强行升级或补造历史。UI 的普通存档绑定可升级后续记录；赛事回放保持原始格式。

真实对局保留完整轨迹。机器人推演复制规则状态时排除观察性的 `log`，保留其规则所需的连锁历史；推演不写入真实轨迹，也不改变随机状态。异常行动仍原子回滚。

普通对局的对手抽卡、未公开盖牌返回手牌等信息不会通过新界面、搜索或导出泄露；本人已知卡片及公开信息可以显示。机器人观战继续按既有公开双方手牌的模式展示。导出保留兼容的 `log` 字段，新增 `format`、版本、展示语言、结局和按回合索引，避免重复存储整段事件。

完整历史会随对局时长增长。UI 分批渲染避免一次创建过多节点；现有保存失败提示及赛事导出能力继续保留。

## 单独记录的旧规则问题

验证时观察到旧的「噩梦之拷问室」事件处理会再次触发自己的追加伤害。在「火花」造成 200 伤害的复现中，追加了多次 300 伤害直到 LP 归零；开启和关闭新轨迹记录均可复现，共 27 条伤害记录。本轮没有将其计为已修复的卡片裁定；它需要单独处理，避免把日志呈现改动和规则变化混在一起。证据在 `output/journal-nightmare-observation.json`，对应旧回调位于 `src/effects-2002-spells.js`。
