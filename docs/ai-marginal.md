# 机器人如何避免重复发动没有额外收益的效果

本次优化针对整个决策流程，并不维护“某张卡只能发动一次”的名单。AI 在主阶段发动、快速响应、可选诱发和同时触发的顺序选择中，共用结算收益判断。

当同名、同效果已经发动过或已有同类卡在场，AI 用独立的引擎副本比较：

1. 保留这一张，按当前已公开的连锁正常处理。
2. 继续发动这一张，再处理当前连锁。

副本执行原有规则，包括逆序结算、无效、目标离场、持续效果来源是否仍在场及实际选择；不会修改正在玩的局面或消耗实局随机数。比较中排除日志、流水号、发动次数记录、被消耗的这张卡以及明确的 LP／指示物等代价，关注 LP、卡片所在区域、手牌与资源、状态、攻击力／守备力、回合限制等实际差异。

如果两种结果相同，就保留这一张。如果多抽牌、多造成伤害、继续增加数值、保护新入场的怪兽、补足失效或已被无效的效果等带来额外结果，就保留发动选项。多张持续陷阱把同一个复活／保护关系从第一张转移到第二张，不算额外一份收益。

相同数值和期限的重复设定、重复召唤限制、同类持续保护的来源记录会先归一化，不把“多写了一条记录”算作收益。持续卡的后续诱发、每张卡分别使用的效果、可累加的数值光环和连续费用也计入；单纯维护费用不计作收益。是否能累加由通用效果模板和规则定义的 `stacking` / `maintenance` 元数据说明，优化器不保存卡名禁发名单。

对于需要目标的效果，AI 还会尝试其他合法目标。例如第一张活死人的呼声已经选择青眼白龙，第二张应当选择墓地的另一只怪兽，而不是再次抢同一个目标、让其中一张空发。目标方案随实际操作记录，保存和录像可以重现。

替代目标沿用原 AI 的目标评分，排除给敌方强化、破坏己方等负收益选择，避免为了让结果不同而反过来帮助对手。

同时触发的可选效果在组成连锁前就比较增量结果；强制触发不会因 AI 认为“不划算”而被取消。人工操作也没有增加新的同名限制。

## 不确定的场景

随机结算、尚未作出的对方选择、无法完整推演的流程或超过推演上限，采用保守策略：保留原 AI 的选择。它不会依据一次模拟的随机结果认定另一张必然无用，也不会借此预测对手将选什么。

这是对重复效果的通用优化，不是穷尽未来所有回合的最优搜索。现有行动评分仍负责何时展开、攻击哪只怪兽等策略。评估结果可通过 `DuelAIMarginal.evaluate()` 检查原因与首个实际差异；普通游玩界面不会显示这些开发信息。

## 顺带纠正的阶段限制

部分旧实现把“同一个下一阶段被跳过”写成了次数累加，导致重复发动得到规则上不应有的额外收益。这次统一纠正时间封印、所罗门的律法书、八汰乌、大天狗、给死者的供物的相应限制；支配者之一括／Thunder of Ruler 限制本回合，不会因本回合没有进入战斗而延后到以后回合。无谋的贪欲原本正确的“最多覆盖接下来两次抽卡阶段”继续保留。

神之宣告等反击陷阱仍遵循速度 3 的响应规则，速度 2 的普通陷阱不能直接连锁它。前一次保护被无效后，AI 会在之后合法的时机重新使用；旋风只是破坏普通魔法／陷阱的来源，并不等于无效已经发动的效果。

## 验证

```powershell
npm.cmd run build
npm.cmd run test:ai
npm.cmd test
npm.cmd run test:tournament
```

专项测试覆盖无收益重复、可叠加数值／抽卡／伤害、不同目标、无效与仅破坏来源、下一回合重新有价值、新怪兽入场、魔法发动带来的额外指示物、同时触发与强制触发、保存恢复、真实 UI 逐步观战及不改变实局状态。原有赛事测试继续比较串行／并行结果和录像一致性。

源码为 `src/ai-marginal.js`，接入点在 `src/advanced-engine.js` 与 `src/advanced-effects.js`；三语新增日志在 `src/i18n-ai.js`。本机报告和截图保存在 `output/ai-marginal-*/`，不提交缓存与测试录像。
