# 卡组工坊：拖拽与空间重排

2026-09-30，依据用户对031b424的截图反馈继续修改。本说明覆盖旧设计中“常驻合法性提示、卡片底部换卡按钮、先选择再应用”的交互约定。

## 当前行为

- 工坊使用完整窗口，桌面左右只留6px边距。名称和排序放入顶部工具栏，主体直接展示卡图。2560×1270实测中央卡组宽1880px，单卡约183px。删除常驻校验框、说明条、卡片底部操作行和“加入位置”选择。
- 从右侧牌库或详情卡图拖入主卡、额外或副卡区，新增一张；分区之间拖动移动该副本；区内拖动调整顺序。顶部三个分区入口也可接收拖拽，方便向当前屏幕外的分区移动。
- 从任一构筑分区拖回牌库即删除；卡片右上角×也可删除。放到非目标区域则取消。每次拖拽或删除可独立撤销、重做。
- 手机长按卡图后拖动；直接滑动仍用于滚动。右键或Shift+F10可打开同样的分区操作，Delete可删除，作为键盘辅助，不占用卡图下方空间。
- 普通草稿允许暂时不足40张、超过分区或同名上限，也可保存、导出和刷新恢复。不在编辑中反复显示合法性提示。开始PVE／观战前同时检查双方构筑，不合法则列出具体原因，并保留当前对局。PVP仍由服务器在准备／开局边界校验。
- BO3换备可以通过临时39/15/16等草稿完成交换，刷新后继续编辑；确认准备时才校验最终张数、类型、同名数量及报名卡池。实际采用的比赛构筑始终合法。局间不能从外部牌库新增或删除报名卡。

## 技术边界

编辑命令统一走DuelDeckEditor.transfer，携带来源分区、准确下标及内部ID，防止同名跨区误删。draft方法只检查结构与可选报名守恒，check／DuelDecks.analyze继续负责完整出战规则；既有AI使用的原子move API保持严格默认值。

DuelDecks.saveDraft显式保存未完成构筑，并标记draft；原save、parseJSON、exportJSON默认严格语义不变。工坊使用允许草稿的导出选项，读入仍保留三分区原文。未知ID不会在装饰卡组信息时造成页面异常，出战校验仍拒绝它。赛事随机池排除不合法草稿，现有已报名快照不受编辑影响。

PVE开局检查位于清理当前界面／引擎之前。PVE和PVP局间草稿恢复采用结构＋报名守恒检查，而不是用最终张数规则丢弃尚未换完的草稿。Match.submit及服务端权威校验保持不变。

牌库和分区使用原生HTML拖拽；详情覆盖层使用捕获指针，避免预览盖住目标或关闭预览时取消浏览器拖拽。触摸使用长按与非被动touchmove，提供随手指移动的卡图、目标高亮和边缘滚动。取消、结束或离开编辑器会清理拖拽状态。控制区与卡图分离，常规展示没有逐卡操作行。
