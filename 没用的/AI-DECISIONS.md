# AI 决策与操作机制说明

> 适用版本：v3（当前线上构建）。入口 `src/game-v2.js` + 引擎 `src/advanced-engine.js`（`ModernDuelEngine`）。
> 结论先行：这套人机**不是搜索算法也不是机器学习**，而是一套「**动作枚举 + 手写评分函数 + 贪心择优**」的规则型 AI。它的全部"棋力"来自每张卡效果定义里手写的分数和条件。

---

## 1. AI 在代码里的位置

AI 没有独立模块，分散在三层：

| 层 | 文件 | 职责 |
|---|---|---|
| 决策入口 | `src/advanced-engine.js:1278` `aiNext()` | 轮到 AI 时，产出"下一个动作" |
| 应答入口 | `src/advanced-engine.js:1236` `chooseAI(pending)` | 引擎弹出的询问框（选素材/选目标/是否响应…）由 AI 代答 |
| 卡片知识库 | `src/effects-*.js`（11 个文件，约 110 处 `aiScore`/`aiResponse`/`aiTrigger`） | 每张卡的效果定义里附带「AI 想不想用、什么时候用、用多想」的分数 |

UI 侧只有一个调度器 `scheduleAI()`（`src/game-v2.js:247`），负责"什么时候去问引擎要下一个 AI 动作"。

另外 `src/engine.js:418` 还保留着 v1 的旧 AI（一长串写死的 if/else 优先级脚本：先抽卡魔法→大风暴→雷击→融合→召唤……），它现在只作为基类存在，已被 `ModernDuelEngine.aiNext` 完全覆盖，实际对局中不会执行。

---

## 2. 运行方式：一次一个动作的外部循环

AI 不是一次算出整回合计划，而是**每 tick 只做一件事，做完重新看局面**：

```
引擎状态变化 → onChange → scheduleAI() →
  延时 220ms(快速模式)/650ms(有询问)/720ms(正常回合) →
  engine.aiNext() 取最优动作 → dispatch(action) →
  引擎结算（可能触发连锁/询问）→ onChange → 回到开头
```

要点（`src/game-v2.js:247-255`）：

- 只有 `state.active === 1`（AI 回合）或询问的应答方是 AI 时才会行动；
- 若询问对象是玩家（`pending.responder === 0`），改为弹出询问弹窗等玩家操作；
- 弹窗打开或页面切走时暂停，关窗后继续；
- `aiEpoch` 令牌保证开新对局后旧计时器不会再落子；
- 若某个 AI 动作派发失败，会弹「对方行动遇到错误，请导出决斗记录」并停下（防死循环的安全阀）。

这种"走一步、看一步"的结构让 AI 对自己动作引发的连锁、触发、局面变化天然自适应——每个动作之后动作列表都是重新枚举的。

## 3. 决策主循环 `aiNext()`

`src/advanced-engine.js:1278-1294`，按顺序四步：

1. **有未决询问？** → 交给 `chooseAI(pending)`（见第 6 节）。
2. **战斗阶段？** → 执行攻击例程（见第 5 节），攻击完转 `main2`。
3. **主要阶段？** → 把当前**所有合法动作**枚举出来逐个打分，取**最高分且 > 0** 的执行。
   - 动作来源：手牌/场上/额外怪兽区/魔陷区/场地/墓地/除外区的每张卡（`actionsFor`，`src/advanced-engine.js:1149`），外加额外卡组的同调/超量/连接召唤选项和灵摆召唤。
   - 合法性完全由引擎校验（`canUse` 会跑一遍 condition/cost/目标数，`src/advanced-effects.js:122`），所以 **AI 永远不会做出规则上不合法的操作**——它只能在引擎认可的动作池里挑。
4. **没有任何正分动作？** → 满足条件（非第 1 回合、有攻击表示怪兽、未被"光之护封剑"封锁）则进入战斗阶段，否则结束回合。

没有任何随机数：给定局面和种子，AI 的选择完全确定（随机性只存在于引擎的洗牌 RNG 里）。

## 4. 主要阶段怎么打分 `actionScore()`

`src/advanced-engine.js:1187-1235`。每种动作一个基准分，再叠加大量按卡名/局面手写的修正项：

| 动作 | 基准分与逻辑 |
|---|---|
| 发动效果 `activate` | 默认 350；若效果定义带 `aiScore`（数字或函数）则优先用它；场上已被无效的卡基本不出场（-100） |
| 通常召唤 `summon` | `380 + ATK/30 + 调整怪+50`，再叠加卡名奖励表（如：手牌有青眼时海马侠 +700、墓地有低星怪时废品同步士 +900、手牌≥2 时哥布林德伯格 +680、场上有电子龙时电子·三 +850…），Qli 上级召唤/免解放各有修正；守备盖放只在「DEF>ATK 且打不过对方最强怪」时小幅加分，效果怪被盖放会扣 450；**祭品代价 = 最便宜祭品组合的 ATK/15 从分数里扣** |
| 额外召唤 `extra-summon` | 固定奖励表（流星龙 1700、机甲要塞∞ 1400、废品增速者 1400、希望皇倍 1100…默认 500）+ `ATK/30`；连接怪走 `E.linkScore`（`src/effects-link.js:90`：按连接怪查表计价值，减去素材损失 `minLoss/12`，亏素材就不召）；部分卡有情景覆盖（如场上有希望皇倍+手牌有乘胜追击时，希望皇闪电只剩 200 分——避免抢素材） |
| 灵摆置刻度 `pendulum-scale` | ~750（同刻度去重 -100；低刻放左/高刻放右有小奖励） |
| 灵摆召唤 | 固定 680 |
| 盖放魔陷 `set` | 只有陷阱卡且后场已盖数 < 2（休闲）/ < 4（标准）时给 180，否则 -100。**这是现代引擎里唯一用到难度的地方** |
| 变更表示 `stance` | 反转/转攻只有在能压过对方某只怪（或对方无怪）时 +260，转守直接 -100 |

另有一个通用估值函数 `cardUtility`（`src/advanced-engine.js:1177`），给"一张卡本身值多少"定价，用于弃牌和素材选择：

- 被禁限制零件 **25000**、检索/抽卡魔法 6000~7500、陷阱 2200、魔法 2500；
- 怪兽 = `ATK + (等级≤4 ? 1500 : 0) + (调整 ? 800 : 0) + aiValue + 关键单卡 2000`。

## 5. 战斗阶段怎么打

`src/advanced-engine.js:1280-1288`，非常直白的贪心：

1. 自己的怪兽按攻击力**从高到低**逐只考虑；
2. 对方场上没怪 → 直接攻击；
3. 否则筛选「**我方攻击力 > 对方该怪价值**」的目标（**只打稳赢的**），在其中挑**价值最高**的打；
   - 对方怪兽的估值 `enemyValue`：里侧表示一律按 1600 算，守备表示按 DEF，攻击表示按 ATK；
4. 有本回合直攻能力的怪（如穿透类）在打不到目标时直接攻击玩家；
5. 全部打完 → 转入主要阶段 2。

被"光之护封剑"封锁攻击时（`attackBlocked`）不会进战斗阶段。

## 6. 被引擎询问时怎么答 `chooseAI()`

`src/advanced-engine.js:1236-1277`，按询问类型分派：

| 询问 | AI 策略 |
|---|---|
| `order`（同时触发排序） | 照候选列表顺序全选 |
| `materials`（选素材） | **融合**：先由 `fusionCombos`（`src/advanced-engine.js:471`）穷举全部合法组合（DFS，上限 80 组），选**素材总 `cardUtility` 最低**的一组（最省的换法）；嵌合兽系列反而选**素材最多**的一组（吃满效果）。**灵摆召唤**：Qli 载体/螺旋优先，其次按 ATK，边选边用 `pendulumValid` 验证。其余（同调/超量/上级召唤祭品）：同样选总价值最低的合法组合 |
| `input`（选目标） | 走 `E.aiPick` → `candidateScore`（见第 7 节），按角色打分后贪心装填，尊重 min/max、去重与校验器（如拟声系列每系最多 1 只） |
| `choice`（二选一/多选一） | 有效果指定的 `preferIds` 就按它排，否则同 `aiPick` |
| `discard`（弃牌） | 弃 `cardUtility` 最低的若干张 |
| `replay`（攻击目标离场后的重新指定） | 优先直攻；否则选「能打过里价值最高」的怪；都打不过就放弃（`cancel`） |
| `trigger`（可选触发效果） | 交给效果定义的 `aiTrigger`；默认=发动（除非发动源在场上已被无效） |
| `window`（响应窗口：对方发动效果/宣告攻击后） | 把所有可响应选项按 `E.aiResponse` 打分，**取最高分且 > 0** 的响应，否则 `pass`。默认分：连锁最后一条是对方的时候给 200（即"默认跟一手"），否则 0 |

## 7. 选目标的通用打分 `candidateScore()`

`src/advanced-effects.js:156-219`。每个输入组带一个 `role`，同一张卡在不同角色下分数完全不同：

- **cost / discard（自己付代价）**：`-cardUtility`（丢最没用的），但「死了更赚」的墓穴饵卡（电子壶、喷气同步士、水晶机巧各级、羽衣精之类）+6000，几乎总会优先送掉；
- **destroy / banish / bounce（解场）**：己方卡 -5000（不误伤）；对方里侧 1700；对方怪兽 `ATK+1200`；永续/场地/灵摆高于普通魔陷；
- **search（检索）**：一张手写的愿望表——检索件本身在场/手重复时大幅降分，缺的关键卡很高（艾克佐迪亚零件 30000、搜索类核心卡 14000~18000）；
- **special（特招）、send-deck（堆墓）、xyz-upgrade（超量升阶）、fusion-choice（融合素材）** 等：各有按卡名写死的偏好表；
- 各卡组模块还能通过 `extraCandidateScore` 链（`src/effects-link.js:82`、`src/effects-tearlaments.js:126`）覆盖默认打分，注入本系列的打法偏好。

**信息公平性**：这些打分全部基于公开信息 + AI 自己的卡。AI 不读取玩家手牌；玩家的里侧怪兽按固定 1600、里侧魔陷按 1700 估值（代码中唯一的 `hand(e,1-owner)` 读取是"暗爪随机除外"的效果结算，与决策无关）。

## 8. 卡片知识库：AI 真正的"棋力"所在

每个效果定义可携带三个 AI 钩子（`src/advanced-effects.js:239-245`）：

- `aiScore(engine, ctx)` —— 自己主要阶段想不想主动用；
- `aiResponse(engine, ctx, window)` —— 对方行动后的响应窗口里想不想跟；
- `aiTrigger(engine, ctx)` —— 可选触发效果要不要开。

典型例子：

| 卡 | 钩子逻辑 |
|---|---|
| 雷击 | `aiScore`：对方场上有怪 1400，否则 -100 |
| 黑洞 | 1300，但只有「对方场面总价值 > 己方 + 500」才肯放（劣势才清场） |
| 强欲之壶 | 卡组 ≥2 张时 1300 |
| D.D.乌鸦 | `aiScore` -100（永远不会主动用），但对方发动墓地效果时 `aiResponse` 2300（专门留着劫墓） |
| 反射镜力 | 对方宣告攻击时 `aiResponse` 1600 |
| 黑旋风 | 通常召唤还没用时 1500（先铺场再动怪），之后 300 |
| 海马侠 | 手牌有青眼白龙时 1500 |
| 珠泪哀歌·塞壬等 | 一整套「连锁最后一条是对方时才响应 1200~2700」的反制分数 |
| 栗子球/羽衣精增伤/槛外之人等 | 用 `damageThreat`（见下）判断——**只有真的要掉血才救** |

**`damageThreat`**（`src/effects-classic.js:6`）是 AI 的"战斗伤害预测器"：对当前攻击窗口，考虑守备表示、贯通怪（电子终极龙、黑羽枪手等）、闸外之人/护封剑类免伤状态后，算出本方实际会掉多少 LP。所有防御性响应（栗子球、羽衣精、槛外之人、电子负载融合的战斗闪躲…）都以它 > 0 为前提——AI 不会无脑交保命卡。

## 9. 难度差异

- **休闲 / 标准**（`difficultyNames`，`src/game-v2.js:25`）：现代引擎里唯一区别是**盖陷阱的后场上限**（休闲 2 张、标准 4 张，`src/advanced-engine.js:1229`）。
- 旧 v1 引擎里休闲难度还允许"同攻击力对撞"，v3 已不再使用该逻辑。

## 10. 特性与局限

**做得好的：**
- 永远合法：所有动作都先过引擎校验，不存在作弊或违规操作；
- 不偷看：不读玩家手牌，里侧卡按固定估值处理；
- 有卡组思路：因为分数表是按系列手写的，黑羽会先黑旋风再展开、珠泪会主动堆墓+融合反制、电子会攒融合素材、Qli 走上贡/刻度体系，甚至懂"希望皇倍→希望皇闪电+乘胜追击"这类组合技的价值变化；
- 可自我对弈验证：`tests/v3-simulation.cjs` 直接让两侧都跑 `aiNext` 打完整局，用于交付前的规则回归。

**局限（设计如此，非 bug）：**
- 纯贪心单步：没有前瞻、没有模拟对方回合、没有博弈树——分数只描述"当下这一手值多少"；
- 不会防守规划：不预判玩家的组合技，只在窗口打开时按 `aiResponse` 分数被动应对；
- 分数全是手写常数：新卡不加 `aiScore` 等钩子的话，AI 对它只有默认 350 分的"发动欲"，不会玩。
